A4. Practical examples & live demos IMPORTANT FOR EXAM

🧪 Demo 1 — Caesar cipher (oldest cipher, not secure)

Each letter moves forward by the "shift" (the key). Anyone can break this by trying 25 shifts — it only teaches the idea of key + algorithm.

To decrypt, enter the ciphertext as the message and use the negative shift (e.g. 3 → −3).

🧪 Demo 2 — SHA-256 hash fingerprint

Type any text. Then change just ONE letter — the whole hash changes (the "avalanche effect"). The same text always gives the same hash. Hashing is one-way: you cannot "decrypt" it.

4. AES vs RSA

PointAESRSA
TypeSymmetric block cipherAsymmetric algorithm
Key128/192/256-bit shared keyPublic/private pair, 2048+ bits
SpeedVery fast (hardware support)Much slower
Data sizeAny size (using a mode such as GCM)Only small data (less than key size)
Main useBulk data encryptionKey exchange/transport, digital signatures
Security basisSubstitution + permutation roundsDifficulty of factoring a large number n = p × q

5. Hashing vs Digital signature

PointHashingDigital signature
Uses a key?NoYes — private key to sign, public key to verify
Gives integrity?Yes (if the hash itself is trusted)Yes
Gives authentication?No — anyone can compute a hashYes — proves who signed
Non-repudiation?NoYes (if private key was kept secret)
RelationshipA signature normally signs the hash of the document, so hashing is a step inside signing.

6. Authentication vs Authorization

PointAuthentication (AuthN)Authorization (AuthZ)
Question"Who are you?""What are you allowed to do?"
HappensFirst (login)After authentication, on every request
MethodsPassword, OTP, biometrics, MFARoles, permissions, access-control lists
ExampleStudent logs into the college portalStudent can see own marks, not other students' marks
Failure codeHTTP 401 UnauthorizedHTTP 403 Forbidden

7. CA vs RA

PointCertificate Authority (CA)Registration Authority (RA)
Main jobIssues, signs, renews and revokes certificatesVerifies the applicant's identity and forwards the request
Signs certificates?Yes, with its private keyNo
Trust levelTrust anchor (root/intermediate)Works under a CA's authority
AnalogyPassport office that prints the passportCounter that checks your documents first

8. Digital certificate vs Digital signature

PointDigital certificateDigital signature
What is it?A document binding an identity to a public keyA value computed over data using a private key
Created byA CAThe signer (owner of the private key)
PurposeProve "this public key belongs to X"Prove "X approved this data and it is unchanged"
RelationshipA certificate contains a CA's digital signature on it. A signature on a document is verified using the public key found in the signer's certificate.

9. HTTP vs HTTPS

PointHTTPHTTPS
Full formHyperText Transfer ProtocolHTTP over TLS (Secure)
Default port80443
EncryptionNone — plain textEncrypted with TLS
CertificateNot neededServer needs a CA-issued certificate

One-page revision sheet IMPORTANT FOR EXAM

🔑 Cryptography

  • Goals: Confidentiality, Integrity, Authentication, Non-repudiation
  • Symmetric: 1 shared key · fast · AES
  • Asymmetric: public+private · slow · RSA
  • Hybrid: asymmetric shares a key → symmetric encrypts data (HTTPS)
  • Hash: one-way, fixed output, SHA-256
  • HMAC: hash + shared secret
  • Signature: hash signed with private key

📜 PKI

  • PKI = people + policies + software + hardware to manage certificates and keys
  • Certificate = identity + public key + CA signature
  • CA signs · RA verifies identity · CSR = request
  • Chain: Leaf → Intermediate → Root
  • Revocation: CRL (list) · OCSP (online query)
  • Browser checks: chain · hostname · dates · revocation

🛡 Secure development

  • Security in every SDLC phase
  • Principles: security by design, least privilege, defence in depth, fail-safe defaults
  • Top bugs: SQLi, XSS, CSRF, broken access control, IDOR
  • Fixes: parameterized queries, output encoding, CSRF tokens, server-side access checks
  • Passwords: Argon2id/bcrypt + salt

🧪 Testing

  • SAST code · DAST running app · SCA libraries
  • Pen test = authorised simulated attack
  • Patch → regression test → monitor

⚠ Remember

  • Base64 ≠ encryption
  • HTTPS padlock ≠ trustworthy site
  • Hash cannot be "decrypted"
  • Never share the private key
  • Client-side validation alone is not security
