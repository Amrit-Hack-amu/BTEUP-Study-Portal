1 Introduction to Information Security 🔵 OFFICIAL BTEUP UNIT 1 SYLLABUS

1. What is Information Security?

Part A — Simple EnglishInformation Security (InfoSec) means protecting information from people or events that can misuse, change, steal, damage or destroy it. Information can be digital (files, database), printed (paper) or even spoken.
Part B — HinglishInformation Security ka matlab hai apni important information ko bachana — galat logon se, galat use se, unwanted changes se aur loss se. Information computer mein ho, kagaz par ho ya cloud mein, sabko protect karna InfoSec hai.
Part C — Real-life exampleCollege ka student database: marks, attendance, fees, Aadhaar-type details. Sirf authorised staff isse dekh/edit kar sake, koi student apne marks na badal sake, aur server kharab ho jaye to bhi data wapas mil sake — ye sab Information Security hai.

2. What is “information” and what are “information assets”?

  • Data = raw facts (e.g., 78, "Rahul", 12-05-2005).
  • Information = data with meaning (e.g., "Rahul scored 78 marks in DBMS").
  • Information asset = any information or thing that stores/processes/transmits information and has value to the organisation: databases, files, servers, laptops, software, network devices, printed records, and even people's knowledge.

Hinglish: Jo cheez organisation ke liye valuable ho aur information se judi ho (server, student database, exam papers, laptop), use information asset kehte hain.

3. Why is Information Security needed?

  • To protect private data of students, customers, employees.
  • To keep business running (a bank cannot work if its data is lost).
  • To follow laws and rules about data protection.
  • To maintain trust — people stop using services that leak data.
  • To avoid financial loss and legal trouble.

🟢 Example: College Database

A college stores: student name, roll number, marks, attendance, fee status.

  • Teacher can view and update attendance only for own subject.
  • Student can view only own marks.
  • Admin keeps a daily backup.
  • Every change to marks is recorded (who, when).

Hinglish: Yahan har person ko sirf utna access diya gaya hai jitna zaroori hai — ye information security ka basic idea hai.

1. How Information Security works (step by step)

  1. Identify assets — list what is valuable (databases, servers, laptops).
  2. Identify threats and vulnerabilities — what can go wrong and where we are weak.
  3. Assess risk — how likely and how damaging?
  4. Choose controls — policies, technical tools, physical protection.
  5. Implement and train people.
  6. Monitor, review and improve regularly.

These three terms are related and overlap, but they are not exactly identical. People often use them loosely in daily talk; in exams, mention the scope difference.

5. Importance in different organisations

  • Colleges: student records, exam results, fee data.
  • Businesses: customer data, trade secrets, accounts.
  • Banks: money, account details, transaction trust.
  • Government: citizen records, public services, national data.

6. Relevant security principles

  • Least privilege — give only the access needed.
  • Need-to-know — share only necessary information.
  • Defence in depth — many layers of protection, not just one.
  • Separation of duties — one person should not control everything (e.g., one prepares marks, another approves).

7. Advantages, limitations, mistakes

  • Advantages: protects data, builds trust, reduces loss.
  • Limitations: no system is 100% secure; security costs time and money; too strict rules reduce convenience.

⚠ Common mistakes

  • Thinking "my data is not important, nobody will attack me".
  • Relying only on antivirus.
  • Ignoring human mistakes (people are a major cause of incidents).

🟢 Practical application

Your college ERP: login (authentication), role-based access (privileges), logs (record), backup/RAID (availability), antivirus on lab PCs.

1. Technical view: Risk analysis

A common simple model: Risk = Likelihood × Impact. Likelihood = chance that a threat exploits a vulnerability; Impact = damage caused. Organisations rank risks (low/medium/high) to decide where to spend effort first.

2. Risk treatment options

OptionMeaningExample
MitigateReduce risk using controlsInstall updates, enable MFA

AvoidStop the risky activityDo not store card details at all
AcceptKnowingly live with low riskVery low-value test PC without backup

3. Practical implementation concepts

  • Security policy (high-level rules) → standards (specific requirements) → procedures (step-by-step tasks).
  • Defence in depth: physical + network + system + application + data + people layers.
  • Attack surface: total points where an attacker could try to enter; reduce by disabling unused services and accounts.

4. Real-world scenario

A college website admin account uses a weak password and no logging. An attacker guesses it, edits results and nobody notices for days. Missing controls: strong authentication, least privilege, audit logs, monitoring, backups. Lesson: one missing layer can break the whole chain.

5. Common failure cases

  • Security added after the system is built instead of during design.
  • Policies exist on paper but are not followed.
  • No backups tested; nobody reviews logs.
  • Ex-employees' accounts remain active.

6. Technical terminology

Attack surfaceExploitResidual riskCountermeasureSecurity postureDefence in depthPolicy / Standard / Procedure

Residual risk = risk that still remains after controls are applied.

7. Interview-level conceptual questions

Q1. Can a system have a vulnerability but no risk?
If no realistic threat can reach or exploit it, or the asset has no value, risk can be very low — but risk is rarely exactly zero, and threats can change over time.
Q2. Why is “defence in depth” better than one strong control?
Any single control can fail. Multiple independent layers mean an attacker must defeat several, and failures are more likely to be detected.
Q3. Is information security only a technical problem?
No. It also involves people (awareness), processes (policies, procedures) and physical protection, along with technology.

P — Privacy

Part A — Simple EnglishPrivacy means protecting personal information and keeping proper control over how it is collected, who can access it, and how it is used.
Part B — HinglishPrivacy ka matlab hai kisi ki personal information ko safe rakhna aur ye control karna ki use kaun dekh sakta hai, kaun collect kar sakta hai aur kis kaam mein use ho sakti hai.
Part C — Real-life exampleStudent portal mein aap sirf apna result dekh sakte ho; doosre student ka phone number ya marks nahi.

Purpose: protect people's personal details from misuse. Importance: prevents identity misuse, embarrassment, fraud, and keeps legal/ethical trust.

A — Authentication

Part A — Simple EnglishAuthentication is verifying identity — checking that a user is really who they claim to be.
Part B — HinglishAuthentication ka matlab hai verify karna ki user sach mein wahi person hai jo hone ka claim kar raha hai.
Part C — Real-life exampleATM mein card (identity claim) + PIN (proof). Mobile unlock: PIN ya fingerprint.

Purpose: make sure only genuine users enter the system. Importance: first gate of security; if it fails, everything behind it is at risk.

I — Integrity

Part A — Simple EnglishIntegrity means information stays accurate, complete and unchanged by unauthorised people (or by accident).
Part B — HinglishIntegrity ka matlab hai data sahi aur poora rahe — koi bina permission ke use badle nahi, aur galti se bhi corrupt na ho.
Part C — Real-life exampleBank balance ₹5,000 hai to wahi dikhna chahiye; koi bina permission 50,000 na kar sake. Marks 78 hain to 87 na ban jaye.

Purpose: keep data trustworthy. Importance: wrong data leads to wrong decisions, money loss and unfair results.

N — Non-repudiation

Part A — Simple EnglishNon-repudiation means providing evidence that a person performed an action or sent a message, so that denying it later becomes difficult (in suitable technical and legal contexts).
Part B — HinglishNon-repudiation ka matlab hai aisa saboot/evidence rakhna ki koi apne kiye hue kaam se aasani se mukar na sake ("maine ye nahi kiya").
Part C — Real-life exampleOnline banking transfer ke baad transaction record + bank ke digital logs; ya digitally signed email/document jisme signer ki identity linked hoti hai.

⚠ Important accuracy note

A plain password alone does not guarantee non-repudiation (passwords can be shared or stolen). Digital signatures and well-protected audit records can support non-repudiation.

CIA Triad (brief)

Confidentiality (only authorised people can read), Integrity (data stays correct), Availability (data/service accessible when needed). It is a different, very common framework. PAIN and CIA overlap (e.g., Privacy ≈ related to Confidentiality; Integrity appears in both) but they are not identical.

📌 Recap

PAIN = Privacy (protect personal info), Authentication (verify identity), Integrity (data correct), Non-repudiation (evidence, accountability).

Detailed study of each element

1) Privacy

  • Working principle: collect minimum data, restrict access, use only for stated purpose, protect storage and transfer.
  • Examples (3): (1) Student portal shows only own marks; (2) Hospital record visible only to treating doctor; (3) Mobile app asks permission before using camera/contacts.
  • Threats/failures: data leak, over-collection, shared screens/passwords, careless sharing on social media.
  • Protection: access control, encryption, privacy settings, data minimisation, staff training.
Short exam answer: Privacy is the protection of personal information and control over its collection, access and use. It is achieved by access control, encryption and data-minimisation policies.

2) Authentication

  • Working principle: user claims identity → provides proof (password, OTP, biometric, token) → system verifies → grants/denies.
  • Examples (3): (1) Student ID + password at portal; (2) ATM card + PIN; (3) Phone fingerprint unlock; (4) OTP for online payment.
  • Failures: weak/reused passwords, phishing, shared accounts, stolen devices, no lockout.
  • Protection: strong passwords, MFA, account lockout, secure password storage, user awareness.
Short exam answer: Authentication verifies a user's claimed identity using something known, possessed or inherent (e.g., password, token, fingerprint) before access is granted.

3) Integrity

  • Working principle: allow changes only by authorised users, detect unauthorised/accidental changes (checksums/hashes, version control, audit logs), and keep backups.
  • Examples (3): (1) Marks cannot be edited by students; (2) File checksum matches after download; (3) Bank transactions cannot be altered silently; (4) Database transaction rules prevent half-saved records.
  • Failures: malware modifying files, insider tampering, disk errors, software bugs, man-in-the-middle changes.
  • Protection: permissions, hashing/checksums, digital signatures, logs, backups, validation rules.
Short exam answer: Integrity ensures information remains accurate and complete and is modified only in authorised ways; it is supported by access control, hashing, digital signatures and backups.

4) Non-repudiation

  • Working principle: bind an action to an identity with evidence — e.g., a digital signature created with a person's private key, plus trustworthy timestamps and audit records.
  • Examples (3): (1) Digitally signed PDF; (2) Bank transaction logs with user ID and time; (3) Email server delivery/sent records; (4) Signed software updates.
  • Failures: shared accounts (cannot prove who acted), stolen private keys, editable logs, no timestamps.
  • Protection: unique user IDs, digital signatures, protected audit logs, time synchronisation, key protection.
Short exam answer: Non-repudiation provides evidence that makes it difficult for a person to deny performing an action or sending a message; digital signatures and protected audit records support it.

⚠ Misconceptions

  • “Authentication = Authorization” ✗ (different; see Topic 3).
  • “Password login proves non-repudiation” ✗.
  • “Privacy and security are identical” ✗ — privacy is about personal data rights/use; security is the protection mechanism.

Technical working

  • Privacy: principles like data minimisation, purpose limitation, consent, retention limits; techniques: encryption, access control, masking/anonymisation.
  • Authentication: verification of credentials; passwords should be stored as salted hashes, not plain text.
  • Integrity: a hash function (e.g., SHA-256) creates a fixed-size fingerprint of data; even a small change gives a very different hash. A MAC/HMAC or digital signature adds authenticity.
  • Non-repudiation: digital signature = hash of message encrypted/signed with the signer's private key; anyone can verify with the public key. Only the key owner can create the signature, so (if the key was protected) the signer cannot easily deny it.
Signing:     message → hash → sign with PRIVATE key → signature
Verification: message → hash → check signature with PUBLIC key → valid / invalid

Security considerations

  • Non-repudiation depends on key protection, correct timestamps, and legal recognition (in India, e.g., IT Act provisions for electronic signatures — verify current rules before quoting in exams).
  • Shared/generic accounts break accountability.
  • Integrity checks must themselves be protected (attacker could change both data and checksum if checksum is unprotected).

Real-world scenario

A clerk changes fee records. Because every clerk has a unique login and the audit log is stored on a separate protected server, the college can identify who changed what and when. If all clerks used one shared account, the evidence would be weak.

Common failure cases

  • Private key stolen → signatures can be disputed.
  • Logs editable by the same admin they monitor.
  • Hash published on the same compromised website as the file.

Interview-level questions

Q1. Difference between integrity and authenticity?
Integrity = data not altered. Authenticity = data really comes from the claimed source. A digital signature can provide both.
Q2. Can encryption alone provide non-repudiation?
Not by itself. Ordinary encryption protects confidentiality. Non-repudiation needs mechanisms like digital signatures plus identity binding and protected evidence.
Q3. Why do shared accounts harm accountability?
Because actions cannot be linked to one individual, so denial becomes easy.

3 Authentication (OS Security Feature) 🔵 OFFICIAL BTEUP UNIT 1 SYLLABUS

1. What is authentication?

Part A — Simple EnglishAuthentication is the process of verifying a user's identity before letting them use a computer, account or service. In an operating system, it is usually the login screen.
Part B — HinglishAuthentication ka matlab hai verify karna ki user sach mein wahi person hai jo hone ka claim kar raha hai. Windows login screen iska best example hai.
Part C — Real-life exampleCollege computer lab mein aap username aur password daalte ho. System check karta hai ki credentials sahi hain ya nahi, tabhi desktop khulta hai.

2. Why needed?

  • Stops strangers from using your account.
  • Makes each action traceable to a user.
  • Base for access control and logs.

3. Identification vs Authentication (basic idea)

Identification = “I am Amit” (claim, e.g., typing username). Authentication = “Prove it” (password/OTP/fingerprint).

🟢 Student portal login example

Username student123 = identification. Password = authentication proof. After success, the portal shows only that student's data.

IdentificationCredentialPasswordOTPBiometricTokenLogin

📌 Recap

Authentication = proving identity. Without it, anyone could pretend to be anyone.

1. Three kinds of proof (authentication factors)

FactorMeaningExamples
Something you knowSecret in your memoryPassword, PIN
Something you haveObject/device you possessOTP on phone, smart card, hardware token
Something you areBody characteristicFingerprint, face

2. Common methods

  • Password-based: simple and common; weak if guessable or reused.
  • OTP-based: One-Time Password valid for a short time/one use (sent by SMS or generated by an app).
  • Token-based: a device or software token proves possession (e.g., hardware key, authenticator). In web systems, a “session token” is also issued after login.
🟠 EXTRA KNOWLEDGE — NOT EXPLICITLY LISTED IN UNIT 1 SYLLABUS

Biometric authentication and Multi-Factor Authentication (MFA)

Biometric: uses body traits (fingerprint, face, iris). Convenient, but cannot be “changed” like a password if the template is compromised, and can have false accepts/false rejects. MFA: uses two or more different factors (e.g., password + OTP). Password + PIN is not MFA because both are “something you know”.

3. Secure login process (best practice)

  1. Enter username and password over a secure (HTTPS) connection.
  2. System compares with stored hashed credential.
  3. Failed attempts are counted and logged; temporary lockout after limit.
  4. Extra factor if required.
  5. Session created with timeout; user logs out when finished.

4. Password security fundamentals

  • Use long passwords/passphrases (e.g., 12+ characters), not personal info.
  • Use a different password for each important account.
  • Do not share passwords; do not write them near the computer.
  • Change if you suspect compromise. Consider a reputable password manager.

5. Authentication failures

  • Wrong password, expired password, locked account.
  • Stolen/guessed passwords, phishing pages.
  • OTP intercepted or user tricked into sharing OTP.
  • Biometric false reject/accept.

⚠ Three common security mistakes

  1. Using the same simple password everywhere (e.g., name + birth year).
  2. Sharing OTP or password with others, even "friends" or callers claiming to be from the bank/college.
  3. Leaving a logged-in computer unlocked in the lab.

🟢 Practical Windows account security example

On your laptop: set a strong password or PIN, enable Windows Hello (if supported), set screen lock after a few minutes (Settings → Accounts → Sign-in options), and never use the same password as your email.

Note: No single authentication method is secure in every situation. Strength depends on how it is implemented, protected and used.

1. Technical working

  • Password storage: systems should store salted hashes (slow hashing algorithms like bcrypt/Argon2/PBKDF2 are used for passwords). “Salt” is random data added to each password before hashing so same passwords give different hashes.
  • OTP: HOTP (counter-based) and TOTP (time-based, e.g., changes every 30 seconds) generate codes from a shared secret.
  • Session tokens: after login a random session ID/token identifies the user for the session; it must be protected and expire.
  • Windows (concept): credentials are checked locally or against a domain controller (e.g., Active Directory); Linux commonly uses PAM (Pluggable Authentication Modules). 🟠 EXTRA KNOWLEDGE

2. Security considerations

  • Brute-force / guessing: defended by lockout, rate limiting, strong passwords, MFA.
  • Phishing: fake login pages steal credentials; user awareness and phishing-resistant methods help.
  • SMS OTP limits: can be affected by SIM-swap or social engineering; app-based or hardware tokens are generally stronger, but each has its own weaknesses.
  • Credential stuffing: attackers try leaked passwords on other sites — reason to never reuse passwords.

3. Practical implementation concepts

  • Account lockout policy, password policy, MFA for admins, secure recovery process (account reset must be verified carefully).
  • Disable/remove unused and default accounts.

4. Real-world scenario

A student reuses the same password on a small gaming site and the college portal. The gaming site is breached; the password is tried on the portal. If the portal enforces MFA and lockout, the attempt is much less likely to succeed.

5. Common failure cases

  • Passwords stored in plain text or with fast, unsalted hashes.
  • No lockout/rate limit; weak recovery questions; shared lab accounts.

6. Terminology

SaltHashTOTPHOTPSession tokenBrute forceCredential stuffingPhishingPAMFalse accept/reject

7. Interview-level questions

Q1. Why should passwords be hashed instead of encrypted?
Hashing is one-way: the system only needs to compare hashes and never needs the original password. If encrypted, a stolen key could reveal all passwords.
Q2. Is password + security question MFA?
No, both are “something you know”, so they are the same factor type.
Q3. What does the salt protect against?
It prevents precomputed (rainbow table) attacks and stops identical passwords from showing identical hashes.

Authentication verifies identity; authorization decides permissions. Factors: know / have / are. MFA needs different factor types (🟠 extra). Use strong, unique passwords; hashed storage; lockouts; logs.

4 Logs 🔵 OFFICIAL BTEUP UNIT 1 SYLLABUS

1. What are logs?

Part A — Simple EnglishA log is a record of events that happen in a computer system — such as who logged in, when, what failed, and what changed. Each entry usually has a timestamp (date and time).
Part B — HinglishLog ek diary/record book jaisa hota hai jisme computer likhta rehta hai ki kab kya hua — kaun login hua, kaun fail hua, kaunsa program band hua.
Part C — Real-life exampleCollege gate ka visitor register: kaun aaya, kis time aaya, kisse milne aaya. Waise hi OS login/logout ka register rakhta hai.

2. Why do operating systems keep logs?

  • To find the reason when something fails (troubleshooting).
  • To detect suspicious activity (many failed logins).
  • To provide evidence after an incident.
  • To monitor system health.

3. Basic types

  • System logs — OS events (startup, shutdown, driver errors).
  • Security logs — login success/failure, permission use, policy changes.
  • Application logs — events from programs (browser, database, web server).

1. How logging works

  3. Entry is saved in a log file/database.
  4. Administrator reviews or software monitors them.
  5. Old logs are archived or deleted according to retention policy.

  • Logs show what was recorded, not everything that happened.

  • Not backing up logs.

  • Time synchronisation (NTP) is critical for correlating events across machines.
  • Privacy: logs may contain usernames, IP addresses or file names — access only for legitimate purposes.
  • Log injection: untrusted input written into logs can confuse analysts; applications should sanitise it.

3. Practical implementation

  • Enable auditing of logon events and important file access.
  • Set adequate log size/retention; alert on repeated failures.
  • Keep a procedure for periodic review.

  • Logs stored only on the compromised machine.
  • Clocks differ by hours between machines.

⚠ Common file-protection mistakes

  • Giving “Everyone – Full control” to a folder.
  • Keeping the only copy of important files on one disk.
  • Storing passwords in plain text files.
  • Not removing access when a team member leaves.

1. Technical working

  • Access Control List (ACL): list of entries (user/group → allowed/denied rights) attached to an object. The OS evaluates them when access is requested.

  • Inheritance (Windows): new files in a folder usually inherit its permissions.
  • Encryption at rest: file-level (EFS, GPG) or full-disk (BitLocker, LUKS).

2. Security considerations

  • Apply least privilege to files (give minimum needed rights).
  • Prefer group-based permissions over many individual users.
  • Keep encryption keys/recovery keys safely and separately.
  • Protect backups too (they contain the same sensitive data).
  • Beware of “deny” rules and inheritance conflicts which can accidentally block or expose data.

3. Practical implementation

  • Create a security group “ProjectTeam”, grant it Modify on the project folder, remove “Everyone”.
  • Follow 3-2-1 backup idea: 3 copies, 2 different media, 1 off-site/offline.
  • Test restoring from backup regularly.

4. Real-world scenario

Ransomware encrypts files a user can write to. Permissions limited the damage to that user's folders, but without offline backups, recovery is difficult. Lesson: permissions reduce impact; backups enable recovery.

5. Failure cases

  • Over-permissive inherited permissions.
  • Backup stored on the same machine.
  • Encryption key lost.

RAID 0 — Striping

  • Definition: data striped across drives, no redundancy.
  • Min drives: 2. Usable capacity: N × S (e.g., 2×1 TB = 2 TB).
  • Fault tolerance: none. If any drive fails, the whole array's data is lost, because pieces of every file are on every drive.
  • Advantages: highest speed, full capacity. Disadvantages: more drives → higher chance of failure; no protection.
  • Use: temporary/scratch data, video editing cache, where data can be recreated.

RAID 1 — Mirroring

  • Definition: same data written to two (or more) drives.
  • Why mirror? So that a complete second copy exists when one drive fails.
  • Min drives: 2. Usable capacity: S for a two-drive mirror (50% efficiency; e.g., 2×1 TB = 1 TB).
  • Fault tolerance: 1 drive failure in a 2-drive mirror.
  • Advantages: simple, fast reads, easy recovery. Disadvantages: costly (half capacity lost), writes go to both drives.
  • Use: OS drives, small important servers, results database.

RAID 5 — Striping + distributed parity

  • Definition: data and parity striped across all drives.
  • Min drives: 3. Usable capacity: (N − 1) × S (e.g., 4×1 TB = 3 TB).
  • Fault tolerance: typically one drive failure, because parity equals the information of one drive and can reconstruct exactly one missing piece per stripe.
  • Advantages: good balance of capacity, speed and protection. Disadvantages: slower writes (parity calculation); rebuild is stressful; second failure during rebuild = data loss.
  • Use: file servers, general storage.

RAID 6 — Striping + double parity

  • Definition: like RAID 5 but with two independent parity blocks per stripe.
  • Min drives: 4. Usable capacity: (N − 2) × S (e.g., 4×1 TB = 2 TB).
  • Fault tolerance: typically two drive failures, because two parity sets can reconstruct two missing pieces.
  • Advantages: safer for large arrays. Disadvantages: lower usable capacity, slower writes, more complex.
  • Use: large storage/archives where rebuild takes long.

RAID 10 (1+0) — Mirroring + striping

  • Definition: drives are mirrored in pairs, and data is striped across the pairs.
  • Why combine? Mirroring gives redundancy; striping gives speed.
  • Min drives: 4. Usable capacity: (N / 2) × S (e.g., 4×1 TB = 2 TB).
  • Fault tolerance: guaranteed 1 drive failure; it can survive more only if the failures are in different mirror pairs. If both drives of one pair fail, data is lost.
  • Advantages: high performance and good protection, quick rebuild. Disadvantages: 50% capacity loss, cost.
  • Use: databases, busy servers.

⚠ Why RAID is not a backup (more detail)

Misconceptions: “RAID 0 is safest” ✗ (it has no redundancy). “RAID 10 can always survive any two failures” ✗. “RAID 1 protects from virus” ✗.

1. Technical working

  • Stripe size / chunk size: amount of data written to one drive before moving to the next.
  • RAID 5 parity: typically XOR of the data blocks in a stripe; parity location rotates among drives (“distributed parity”) to avoid a parity-drive bottleneck.
  • RAID 6: uses two independent parity calculations (commonly XOR-based P plus a second code Q, such as Reed–Solomon-style) so two missing blocks can be solved.
  • Write penalty: updating data in parity RAID may require reading old data/parity and writing new data/parity (the “read-modify-write”).

2. Security / reliability considerations

  • Rebuild risk: during rebuild, remaining drives are stressed; a second failure in RAID 5 means loss. Larger drives = longer rebuild.
  • Hot spare: an idle drive that automatically replaces a failed drive. 🟠 EXTRA KNOWLEDGE
  • Hardware vs software RAID: hardware uses a RAID controller; software RAID is managed by the OS. Controller failure can complicate recovery. 🟠 EXTRA KNOWLEDGE
  • Silent corruption can be copied into parity/mirrors; RAID does not guarantee data correctness.
  • Monitoring: alerts for degraded arrays; replace failed drives promptly.

3. Practical implementation concepts

  • Use drives from different batches where possible; label and document array layout.
  • Test restore from backup separately from RAID.
  • Keep UPS/power protection to reduce write-hole/power-loss issues.

4. Real-world scenario

A college file server uses RAID 5 with four drives. One drive fails and the server continues in degraded mode. The admin replaces it and the array rebuilds. Meanwhile, a second old drive shows errors. Because the admin also has a nightly offline backup, the college is safe. Without the backup, the second failure could have meant data loss.

5. Common failure cases

  • Ignoring degraded-array warnings.
  • Using RAID 0 for important data.
  • No backup because “we have RAID”.
  • Mixing very different drives, limiting capacity/performance.

7. Interview-level questions

Q1. Why does RAID 5 tolerate only one drive failure?
It stores one drive's worth of parity information per stripe, which can recompute exactly one missing block per stripe.
Q2. RAID 10 vs RAID 5?
RAID 10: better write performance and faster rebuild, 50% capacity. RAID 5: more usable capacity, but slower writes and riskier rebuild.
Q3. Can RAID replace backup?
No. It addresses drive failure only, not deletion, malware, corruption or disasters.

  • RAID 0: striping; min 2 drives; capacity N×S; no fault tolerance (any drive failure loses data); fastest; used for non-critical temporary data.
  • RAID 1: mirroring; min 2; capacity S (two-drive mirror); tolerates one drive failure; simple, reliable; half capacity lost.

  • RAID 10: mirrors striped together; min 4; capacity (N/2)×S; survives one failure for sure, more only if in different mirror pairs; high performance; 50% capacity lost.

Question 5 — Antivirus Software

Question (simple English): What is antivirus software? Explain its working and role in operating-system security. Mention its limitations.

Full answer

Antivirus software is a security program that detects, blocks and removes malware (malicious software) such as viruses, worms and Trojans.

MalwareMeaning
VirusAttaches to files/programs and spreads when they are run
WormSelf-replicates across networks without needing a host file
TrojanPretends to be useful but performs harmful actions
New file / USB / download
Real-time scan
Signature + heuristic check
Threat → Quarantine / remove
  • Signature-based detection: compares files with known malware patterns.
  • Heuristic detection: looks for suspicious behaviour or characteristics; can detect some unknown threats but may give false positives.
  • Real-time protection, scanning, quarantine, updates are key features.

Role in OS security: It protects files, memory and removable media; reduces malware infection; works with firewall, updates, user privileges and backups as part of layered security. Example: Microsoft Defender in Windows Security.

Limitations: cannot guarantee 100% protection; new malware may not be detected immediately; cannot stop user mistakes such as sharing passwords; needs updates; may produce false positives.

Antivirus vs firewall: antivirus deals with malicious files/programs; firewall controls network traffic. They complement each other.

Safe habits: update systems, avoid pirated software, don't open unknown attachments, keep backups, do not disable protection.

B. 10 Short-Answer Questions

1. Define Information Security.
Show answer
Protection of information in any form from unauthorised access, misuse, modification, loss or destruction.
2. Differentiate threat, vulnerability and risk.
Show answer
Threat: potential cause of harm. Vulnerability: weakness that can be exploited. Risk: possible loss when a threat exploits a vulnerability (considering likelihood and impact).
3. Expand PAIN and define Privacy in one line.
Show answer
Privacy, Authentication, Integrity, Non-repudiation. Privacy = protection of personal information and control over its collection, access and use.
4. Why is a password alone not enough to guarantee non-repudiation?
Show answer
Passwords can be shared, guessed or stolen, so an action cannot be firmly linked to one person. Digital signatures with protected keys and secure audit records give stronger evidence.
5. List three types of logs maintained by an OS.
Show answer
System logs, security logs and application logs.
6. Give one difference between logging and auditing.
Show answer
Logging records events; auditing reviews records against policy to check compliance and accountability.
7. Why should everyday users not use administrator accounts?
Show answer
Malware or mistakes running with admin rights can change system settings or damage the whole system; standard accounts limit damage (least privilege).
8. Why does RAID 5 usually tolerate only one drive failure, and RAID 6 two?
Show answer
RAID 5 stores one set of parity (one drive's worth) which can rebuild one missing block per stripe. RAID 6 stores two independent parity sets, so two missing blocks can be rebuilt.
9. Distinguish virus, worm and Trojan.
Show answer
Virus attaches to files and spreads when run; worm self-replicates over networks; Trojan disguises itself as useful software and usually does not self-replicate.
10. How do antivirus and firewall differ?
Show answer
Antivirus detects/removes malware in files and processes; firewall filters network connections. They complement each other.

C. 5 True / False Questions

1. A plain password alone guarantees non-repudiation. (True/False)
Show answer
False. Passwords can be shared or stolen; non-repudiation needs stronger evidence like digital signatures and protected audit records.
2. RAID 1 protects you if you accidentally delete a file. (True/False)
Show answer
False. The deletion is applied to both mirrored copies. Backups are needed.
3. Using a standard user account for daily work can reduce damage from malware. (True/False)
Show answer
True. Malware inherits the privileges of the account it runs under.
4. If antivirus is installed, a computer is 100% safe. (True/False)
Show answer
False. Antivirus has limitations: new threats, user mistakes and missed detections.
5. Authorization normally happens after authentication. (True/False)
Show answer
True. The system first identifies who you are, then decides what you may do.

D. 5 Scenario-Based Questions

1. A student uses the same password for the college portal, email and a gaming site. The gaming site reports a data leak. What should the student do and why?
Show answer
Change the password immediately on all important accounts, using a different strong password for each; enable MFA where available (🟠); check account activity; consider a password manager. Reason: attackers try leaked passwords on other sites (credential stuffing).
2. The internal-marks file was modified at 11:45 PM. How can the administrator investigate, and what controls would you recommend?
Show answer
Check audit/file-access records and security logs around that time (who, which machine), review login attempts, protect and preserve evidence, restore the file from backup, reset affected accounts and report to the authority. Recommend unique accounts, stronger passwords/lockout, tighter file permissions, regular log review and audit policy.
3. In a lab, all students have administrator rights and malware keeps returning. Suggest improvements.
Show answer
Switch students to standard accounts, restrict software installation, keep OS/antivirus updated, enable firewall, disable auto-run from USB or scan removable media, keep an admin account only for technicians, enable logging/auditing and provide user awareness training.
4. A small office stores important accounts data on a RAID 0 array and says “our data is safe”. Is this correct? What do you advise?
Show answer
Not correct: RAID 0 has no redundancy; one drive failure loses all data. Advise RAID 1/5/6/10 depending on needs, plus regular tested backups (3-2-1), since RAID itself is not backup.
5. Your antivirus warns that a downloaded file is suspicious. What should you do?
Show answer
Do not open or run it. Let the antivirus quarantine/remove it, check protection history, keep protection enabled, update definitions and run a scan, and report to the lab incharge/IT if it is a college system. Download software only from trusted sources.
