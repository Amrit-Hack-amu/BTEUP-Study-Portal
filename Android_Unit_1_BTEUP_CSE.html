1.1 Introduction to Android IN BTEUP SYLLABUS
Definition (English): Android is a free and open-source mobile operating system based on the Linux kernel. It is developed by Google and is used in smartphones, tablets, smart TVs, smartwatches and cars.
Definition (Hinglish): Android ek free aur open-source mobile operating system hai jo Linux kernel par bana hai. Isse Google develop karta hai. Hamare mobile, tablet, smart TV aur smartwatch me yahi chalta hai.

Detailed explanation (English)

An operating system (OS) is the main software that controls the hardware (screen, camera, battery, network) and lets apps run. Android is such an OS for touch-screen devices. It was first created by Android Inc. (2003), bought by Google in 2005, and the first phone with Android was released in 2008. Developers write apps mostly in Java or Kotlin, design screens in XML, and publish apps on Google Play Store.

Detailed explanation (Hinglish)

Operating system wo software hota hai jo hardware (screen, camera, battery) ko control karta hai aur apps ko chalne deta hai. Jaise computer me Windows hai, waise mobile me Android hai. Android open-source hai, matlab koi bhi company (Samsung, Xiaomi, Realme) isse use kar sakti hai. Isliye Android phones sasta se mehenge tak sab range me milte hain.

Real-life example

When you open WhatsApp, tap the camera icon, and take a photo – Android gives WhatsApp permission to use the camera hardware. Android is the "manager" between the app and the phone.

Practical example

A simple Android app: a "Calculator" app made with Java + XML. The XML draws buttons; Java adds the logic (2 + 3 = 5). Android runs it on any phone.

Important features

  • Open-source and free
  • Based on Linux kernel
  • Touch-screen friendly user interface
  • Multitasking and background services
  • Huge app store (Google Play)
  • Supports Wi-Fi, Bluetooth, GPS, sensors, camera

Advantages & Disadvantages

AdvantagesDisadvantages
Free and open-source; many device choices; easy app development; large community; customizableMany versions (fragmentation); security risks from unknown apps; battery drain by background apps; updates depend on the manufacturer

Working process (step-by-step)

  1. Developer writes the app in Java/Kotlin + XML.
  2. The code is compiled into an APK file.
  3. APK is installed on the device.
  4. Android starts a separate process for the app and runs it using ART.
  5. The app asks Android for hardware access (camera, internet) through the framework.

Important terms

OS, Open Source, Linux Kernel, APK, Google Play, Java/Kotlin, OHA (Open Handset Alliance)

Diagram

User→Android App→Android OS→Hardware
Exam short note: Android = open-source, Linux-based mobile OS by Google (first phone 2008). Apps written in Java/Kotlin, distributed as APK, sold on Play Store.

1.2 The Android Platform IN BTEUP SYLLABUS
Definition (English): The Android platform is the complete software stack (a group of layers) that includes the operating system, middleware, libraries, runtime and key applications needed to run Android apps.
Definition (Hinglish): Android platform ka matlab hai Android ka poora software stack – Linux kernel se lekar apps tak sab layers ka group. Isse hi "Android architecture" bhi kehte hain.

Detailed explanation (English)

The platform is built in layers. Each layer uses the services of the layer below it: (1) Linux Kernel, (2) Hardware Abstraction Layer (HAL), (3) Native C/C++ Libraries and Android Runtime (ART), (4) Java API Framework, (5) System Apps / User Apps. A developer usually works at the top two layers.

Detailed explanation (Hinglish)

Platform ko ek 5-manzil building samjho. Sabse neeche Linux kernel (foundation) hai, upar HAL, phir libraries + ART, phir Framework, aur sabse upar apps. Har upar wali layer neeche wali layer ki service use karti hai.

Real-life example

Like a building: foundation (Kernel), pipes and wiring (HAL, Libraries), management office (Framework), and flats where people live (Apps).

Practical example

When an app calls Camera.open(): App → Framework (Camera Service) → HAL (camera module) → Kernel (camera driver) → Camera hardware.

Features

  • Layered and modular design
  • Open source (AOSP)
  • Rich application framework
  • Optimised runtime (ART)
  • Hardware independent through HAL

Advantages & Disadvantages

AdvantagesDisadvantages
Easy to update one layer; same app runs on many devices; secure process isolationComplex for beginners; layers add some overhead; manufacturer changes cause differences

Working process

  1. Phone boots → Linux kernel loads drivers.
  2. Android system services start.
  3. Home screen (launcher app) opens.
  4. User taps an app → framework starts the app process with ART.

Important terms

Kernel, HAL, ART, Framework, AOSP, Stack

Diagram

Apps↓Framework↓Libraries + ART↓HAL↓Linux Kernel
Exam short note: Android platform = 5-layer stack: Applications, Java API Framework, Native Libraries + ART, HAL, Linux Kernel. (Full details in Section 2.)

1.3 Android SDK IN BTEUP SYLLABUS

Definition (Hinglish): Android SDK ek toolbox hai. Isme wo sab tools hote hain jinse hum Android app banate, test karte aur debug karte hain – jaise compiler, emulator, ADB, libraries.

Without the SDK you cannot build an Android app. It provides the Android API libraries (android.jar), Build Tools (to make APK), Platform Tools (ADB), Emulator (virtual phone), SDK Manager (to download versions) and sample code.

Detailed explanation (Hinglish)

Jaise carpenter ko hammer, saw, drill chahiye, waise Android developer ko SDK chahiye. SDK Manager se hum alag-alag Android versions (API levels) download kar sakte hain.

A mechanic's toolbox: spanner, screwdriver, tester – each tool has a job. SDK is the developer's toolbox.

Practical example

Command adb devices (from Platform Tools) lists connected phones; adb install app.apk installs your app.

Features

  • Contains API libraries for each Android version
  • Emulator to test without a phone
  • Debugging tools (ADB, Logcat)
  • Build tools to create APK
  • Free to download

Advantages & Disadvantages

Free; all tools in one place; supports many versions; good documentationLarge download size; needs good RAM/disk; emulator can be slow on weak PCs

Working process

  1. Install SDK (with Android Studio or Eclipse).
  2. Open SDK Manager and download needed platform (API level).
  3. Write code; build tools compile it into an APK.
  4. Run on emulator or device using ADB.
  5. Debug using Logcat.

Important terms

SDK, API Level, SDK Manager, ADB, AVD, Build Tools, Platform Tools

Diagram

1.8 Android Manifest File IN BTEUP SYLLABUS
Definition (English): AndroidManifest.xml is a compulsory XML file in every Android app that gives Android essential information about the app: its components, permissions, and launcher screen.
Definition (Hinglish): AndroidManifest.xml app ka "ID card" hai. Isme likha hota hai ki app ka naam kya hai, kaun si Activities/Services hain, kaun si permissions chahiye aur pehli screen kaun si hai.

Detailed explanation (English)

Android reads the manifest before running any code. The root tag is <manifest>, and inside it are <uses-permission> and <application>, which contains <activity>, <service>, <receiver> and <provider>. An <intent-filter> with MAIN + LAUNCHER marks the first screen.

Detailed explanation (Hinglish)

Agar aapne koi nayi Activity banayi lekin Manifest me register nahi ki, to app crash ho jayega. Isi tarah Internet use karna hai to INTERNET permission Manifest me likhni padegi.

Real-life example

A college admission form/ID card: it tells the college who you are, which courses you take and what facilities you may use.

Practical example

Adding <uses-permission android:name="android.permission.INTERNET"/> lets the app use the internet.

Features

  • Exactly one per app, in the root
  • Declares all four components
  • Declares permissions and hardware needs
  • Names the launcher Activity

Advantages & Disadvantages

AdvantagesDisadvantages
Central place for app info; improves security (permissions); Play Store reads it for device filteringOne XML mistake can stop the build; must be updated manually for each new component

Working process

  1. App installed → Android reads manifest.
  2. Permissions are noted (user approves dangerous ones).
  3. User taps icon → Android finds the LAUNCHER activity.
  4. That Activity starts.

Important terms

<manifest>, <application>, <activity>, Intent Filter, Permission, LAUNCHER, minSdkVersion

Diagram

<manifest>→<uses-permission>+<application>→<activity> + intent-filter
Exam short note: Manifest = mandatory XML (AndroidManifest.xml) declaring components, permissions and launcher activity.

2.5 Android Architecture (with labelled diagram) IN BTEUP SYLLABUS

Android architecture is a stack of 5 layers. (Hinglish: Android ki structure 5 layers ki stack hai, neeche se upar tak.)

Figure: Android Architecture (bottom = Linux Kernel, top = Applications)

Layer-by-layer explanation

1. Linux Kernel

The foundation. It handles process management, memory management, security, power management, networking and contains device drivers (display, camera, Wi-Fi, Bluetooth, audio). The special Binder IPC driver lets apps and services talk to each other.

Hinglish: Kernel hardware se seedha baat karta hai – memory, battery, drivers sab yahi sambhalta hai. Android ki "neev" (foundation).

2. Hardware Abstraction Layer (HAL)

HAL gives standard interfaces to the upper layers so they can use hardware without knowing its details. It has separate library modules for camera, audio, Bluetooth, sensors, etc. Because of HAL, one Android framework works with hardware from many companies.

Hinglish: HAL ek "translator" hai. Framework bolta hai "photo kheencho", HAL us company ke camera driver ko samajh kar kaam karwata hai.

3a. Native Libraries

Written in C/C++ for speed: libc (standard C), SQLite (database), OpenGL ES (2D/3D graphics), WebKit/Chromium (browser engine), Media Framework (audio/video), SSL (security), Surface Manager. Apps use them through the Java framework.

3b. Android Runtime (ART)

ART is the engine that runs the app's code. App code is compiled into DEX (Dalvik Executable) bytecode; ART compiles it to native machine code using AOT (Ahead-of-Time) (plus JIT and profile-guided compilation in newer versions). Each app runs in its own process with its own ART instance. ART replaced the older Dalvik VM in Android 5.0 (Lollipop) and gives faster apps, better battery and improved garbage collection. It also contains the core Java libraries.

Hinglish: ART app ke code ko mobile ki language me convert karke chalata hai. Pehle Dalvik tha, ab ART hai jo zyada fast hai.

4. Java API Framework (Application Framework)

The set of Java/Kotlin APIs that developers use. Main managers:

  • Activity Manager – controls activity lifecycle and navigation.
  • Content Providers – share data between apps (e.g., contacts).
  • View System – buttons, lists, text boxes for the UI.
  • Package Manager – knows installed apps.
  • Telephony Manager – calls and SMS info.
  • Resource Manager – strings, images, layouts.
  • Location Manager – GPS data.
  • Notification Manager – status bar alerts.

5. Android Applications

The top layer which the user sees. System apps (Phone, SMS, Camera, Browser, Email) come preinstalled; user apps are installed from Play Store or APK. A developer's app sits here and uses the Framework below.

Exam tip: Draw the diagram with 5 layers and write 2–3 lines on each. Memorise: "Kernel – HAL – Libraries/ART – Framework – Apps".

Tools used to communicate with Android devices: mainly ADB and Fastboot.

3.5 Emulator & SDK Platforms IN BTEUP SYLLABUS

Emulator: A virtual Android phone running on your PC, created using an AVD (Android Virtual Device). You can choose screen size, Android version and RAM. Advantage: test on many devices without buying them. Disadvantage: uses a lot of RAM and CPU.

SDK Platforms: Each Android version has a platform package. When you set compileSdk / target version, the SDK uses that platform's android.jar.

3.6 How Android SDK Works (step-by-step) IN BTEUP SYLLABUS
  1. You write Java/Kotlin code and XML layouts.
  2. Compiler uses android.jar (from SDK Platform) to check your code.
  3. Build tools compile code into .class files, then .dex.
  4. Resources are packed by aapt2.
  5. Everything is bundled into an APK and signed.
  6. ADB installs the APK on the emulator/device.
  7. The app runs; Logcat shows messages for debugging.
Java/XML→.class→.dex→APK→ADB install→Run

Practical example: You click ▶ Run in Android Studio. Behind the scenes Gradle calls build tools, then ADB installs the APK on the emulator and starts MainActivity.

8.1 What is AndroidManifest.xml & why is it required? IN BTEUP SYLLABUS
Definition: AndroidManifest.xml is a mandatory XML file placed in the root of every Android app. It describes the app to the Android system: its package name, components (Activities, Services, Receivers, Providers), required permissions, hardware/software needs and the launcher Activity.
Hinglish: Manifest file app ka introduction-form hai jo Android system ko bataata hai ki "mera app kya hai, kya-kya use karega aur kahan se shuru hoga".

Why is it required?

  1. Android must know the components of the app before running any code.
  2. It declares permissions the app needs (Internet, Camera…).
  3. It marks the launcher Activity (entry point).
  4. It gives the app name, icon and theme.
  5. Google Play uses it to decide which devices can install the app.

Q1. Explain Android architecture with a neat labelled diagram. 5 MARKS – IMPORTANT

Definition: Android architecture is the layered software stack of Android, in which each upper layer uses the services of the layer below it. It has five layers.

Explanation of layers:

  1. Linux Kernel: Bottom layer. Manages memory, processes, power, security and contains device drivers (display, camera, Wi-Fi, Bluetooth). Binder IPC allows communication between processes.
  2. Hardware Abstraction Layer (HAL): Gives standard interfaces so the framework can use hardware (camera, audio, sensors) without knowing hardware details.
  3. Native Libraries: C/C++ libraries such as SQLite (database), OpenGL ES (graphics), WebKit (browser), libc, Media framework.
  4. Android Runtime (ART): Runs app code (DEX bytecode) using AOT compilation; each app runs in its own process. Replaced Dalvik in Android 5.0. Contains core Java libraries.
  5. Application Framework: Java APIs used by developers: Activity Manager, Content Providers, View System, Package Manager, Notification Manager, Location Manager, Resource Manager.
  6. Applications: Top layer. System apps (Phone, Contacts, Browser) and user-installed apps.

Conclusion: This layered design makes Android secure, modular and hardware independent.

Q2. What is Android SDK? Explain its components. 5 MARKS – IMPORTANT

Definition: The Android SDK (Software Development Kit) is a collection of tools, libraries, an emulator and documentation required to design, build, test and debug Android applications.

Why needed: It supplies the Android API libraries, build tools to create an APK, an emulator for testing, and debugging tools.

Components:

  1. SDK Manager: Tool to download and update SDK platforms, tools and system images.
  2. SDK Platforms: A package for each Android version (API level) containing android.jar library.
  3. Platform Tools: Tools that communicate with devices, mainly ADB (Android Debug Bridge) and Fastboot.
  4. Build Tools: Tools like aapt2, d8, zipalign and apksigner to compile, align and sign the APK.
  5. Emulator (AVD): A virtual Android device used to test apps without a real phone.
  6. System Images: Android OS images used by the emulator.
  7. Documentation and Samples: Help files and example code.
SDK→Manager | Platform Tools | Build Tools | Platforms | Emulator

Working: Code is compiled using SDK libraries → build tools create APK → ADB installs it on emulator/device → Logcat helps debugging.

Conclusion: Without the SDK no Android application can be developed.

Q3. Explain the features of the Android platform. 5 MARKS – IMPORTANT

Introduction: Android is a free, open-source, Linux-based mobile operating system developed by Google. Its platform provides many features which made it the most popular mobile OS.

Main features:

  1. Open source: The source code (AOSP) is free; manufacturers and developers can modify it.
  2. Multitasking: Many apps can run together; background services are supported.
  3. Rich user interface: Touch screen, gestures, widgets, themes and Material Design.
  4. Connectivity: Supports Wi-Fi, Bluetooth, GSM/4G/5G, NFC and USB.
  5. Storage: SQLite database, shared preferences and file storage.
  6. Multimedia support: Audio, video and image formats; camera access.
  7. Sensors and location: GPS, accelerometer, gyroscope, proximity sensor.
  8. Google services integration: Play Store, Maps, Gmail, Firebase.
  9. Security: Each app runs in its own sandbox with a permission system.
  10. Customisable and scalable: Works on phones, tablets, TVs, watches and cars; manufacturers add custom skins.
  11. Hardware independence: Because of HAL one app runs on many devices.

Conclusion: These features make Android flexible, powerful and developer-friendly.

Q7. Explain the anatomy of an Android application. 5 MARKS – IMPORTANT

Definition: The anatomy of an Android application is the structure of an Android project: the folders and files and the role of each.

app/ ├── manifests/AndroidManifest.xml ├── java/com.example.app/MainActivity ├── res/ │ ├── drawable/ (images) │ ├── layout/ (activity_main.xml) │ ├── mipmap/ (launcher icons) │ └── values/ (strings, colors, themes) ├── assets/ (raw files) └── Gradle Scripts (build.gradle)
  1. manifests: contains AndroidManifest.xml – app information, components, permissions.
  2. java: contains source code, e.g., MainActivity, which controls the screen.
  3. res: resources: layout (UI in XML), drawable (images, shapes), mipmap (launcher icons), values (strings.xml text, colors.xml, themes.xml).
  4. assets: raw files such as fonts, JSON, HTML, accessed by AssetManager.
  5. Gradle scripts: build.gradle defines SDK versions, application ID and dependencies.
  6. R class: auto-generated class that holds IDs of all resources.

Working together: Manifest identifies launcher Activity → Activity runs setContentView() → layout XML loads → resources supply text, colours and images → Gradle builds all into APK.

Q8. Explain the structure and importance of AndroidManifest.xml. 5 MARKS – IMPORTANT

Definition: AndroidManifest.xml is a compulsory XML file in the root of every Android app. It gives the Android system essential information about the application.

Structure:

<manifest package="com.example.myfirstapp">
  <uses-permission android:name="android.permission.INTERNET"/>
  <application android:icon="@mipmap/ic_launcher"
               android:label="@string/app_name"
               android:theme="@style/AppTheme">
    <activity android:name=".MainActivity" android:exported="true">
      <intent-filter>
        <action android:name="android.intent.action.MAIN"/>
        <category android:name="android.intent.category.LAUNCHER"/>
      </intent-filter>
    </activity>
    <service android:name=".MyService"/>
    <receiver android:name=".MyReceiver"/>
    <provider android:name=".MyProvider" android:authorities="com.example.provider"/>
  </application>
</manifest>

Importance:

  1. Declares the package name – unique identity of the app.
  2. Registers all components: Activity, Service, Broadcast Receiver, Content Provider. An unregistered Activity causes a crash.
  3. Declares permissions (Internet, Camera) needed by the app.
  4. Defines the launcher Activity through the MAIN/LAUNCHER intent filter.
  5. Specifies app icon, label and theme, and minimum/target SDK.
  6. Google Play uses it to filter devices.

Q10. Explain the role of different Android application components. 5 MARKS – IMPORTANT

Introduction: Application components are the essential building blocks of an Android app. Each component has its own purpose and lifecycle and must be declared in the manifest. There are four main components.

  1. Activity: Represents a single screen with a user interface. Example: login screen. It is a subclass of AppCompatActivity; lifecycle methods are onCreate(), onStart(), onResume(), onPause(), onStop(), onDestroy().
  2. Service: Runs long-running tasks in the background without UI. Example: playing music, downloading a file. Subclass of Service.
  3. Broadcast Receiver: Responds to system-wide or app announcements (broadcasts). Example: battery low, SMS received, device boot completed. Subclass of BroadcastReceiver (method onReceive()).
  4. Content Provider: Shares structured data between apps through a common interface. Example: Contacts and Media data. Subclass of ContentProvider.
