OFFICIAL PRACTICALPractical 1 — Knowledge of Security Provided by Windows Operating System

Aim: To study and observe the built-in security features of the Windows operating system (Microsoft Defender, Firewall, Updates, User Accounts, File Permissions) on your own Windows 10/11 PC.

Objectives:

  • Understand what "Operating System Security" means.
  • Identify the difference between a Standard user and an Administrator.
  • Open and explore the Windows Security app.
  • Observe file permissions on a sample file.
  • Record genuine, truthful observations from your own PC.
🟢 LEVEL 1 — BASIC

A. Simple English

Operating System Security means the set of built-in tools an OS (like Windows) provides to protect your data, your identity, and your computer from unauthorized access, viruses, and misuse.

B. Hinglish

Operating System Security ka matlab hai — Windows apne andar kuch "suraksha ke tools" leke aata hai, jaise ek ghar mein taala, CCTV, aur guard hota hai. Yeh tools aapke data aur PC ko hackers, virus, aur galat logon se bachate hain.

C. Real-life example

Jaise college computer lab mein har student ka alag login account hota hai (Standard user), aur sirf lab-incharge ke paas Administrator password hota hai jo software install kar sakta hai — yeh ek "access control" ka real example hai.

Important terms:

TermSimple meaning
Administrator accountFull control account — can install software, change settings, manage other users.
Standard user accountLimited account — can use apps but cannot change system-wide settings.
Microsoft Defender AntivirusWindows' built-in free antivirus and anti-malware engine.
FirewallA filter that controls which network traffic is allowed in/out of your PC.
Windows UpdateMechanism that delivers security patches to fix known vulnerabilities.
File permissionRule that decides who can read/write/execute a specific file or folder.

Requirements: A Windows 10 or 11 PC with at least a Standard user login; no extra software needed (all tools are built-in).

Simple exercise: Press Win key → type "Windows Security" → press Enter. Just look at the home screen and note the green ✔ marks.

🟡 LEVEL 2 — INTERMEDIATE (Step-by-step Procedure)
  1. Open Windows Security: Click Start → type Windows Security → Open. (On some PCs: Settings → Privacy & Security → Windows Security).
  2. Check Virus & threat protection: Click this tile. Note "Last scan" time and whether real-time protection is ON.
  3. Check Firewall & network protection: Click this tile. Note which network profile (Domain/Private/Public) is active and whether the firewall is ON for it.
  4. Check for updates: Settings → Windows Update → Check for updates. Note the Windows version/build number and pending updates.
  5. Identify account type: Settings → Accounts → Your info (shows if you are Administrator), or Settings → Accounts → Family & other users to see all accounts and their type.
  6. Inspect file permissions: Create a test file (e.g. test.txt) on Desktop → Right-click → Properties → Security tab → note listed users/groups and their permissions (Read, Write, Full control).
  7. Review sign-in options: Settings → Accounts → Sign-in options. Note which methods are available (PIN, Password, Windows Hello, Picture password) — availability depends on your hardware.
  8. Record observations in the practical record table below.
Windows 11's Settings layout differs slightly from Windows 10 (e.g., "Windows Update" placement). If a menu item isn't where described, use the Settings search box at the top and type the feature name — this works the same on both versions.

Result: The security features offered by the Windows operating system on the test PC were successfully identified, opened, and recorded.

Troubleshooting:

  • "Some settings are managed by your organization" — This appears on college/office PCs because of Group Policy. It is normal; do not try to disable it. Just note it in observations.
  • Security tab missing in file Properties — Only appears on NTFS-formatted drives, not FAT32/exFAT. Check drive format via "This PC" → right-click drive → Properties.
  • Can't see Administrator option — You may be logged in as a Standard user; this itself is a valid observation about least-privilege design.
🔴 LEVEL 3 — ADVANCED

🟠 Advanced / Extra Knowledge:

  • Principle of Least Privilege: Users should only be given the minimum access needed to do their job — this is why most real-world accounts (including student lab accounts) are Standard, not Administrator.
  • Device encryption / BitLocker: Available on Windows 11 Pro/Enterprise and many modern devices; encrypts the entire drive so data is unreadable without the recovery key. Availability depends on edition and hardware (TPM chip).
  • Secure Boot: A firmware-level (UEFI) feature that only allows digitally signed, trusted boot software to run, blocking boot-level malware (rootkits).
  • Endpoint security: In organizations, Windows Defender is often combined with centrally managed tools (Endpoint Detection and Response / EDR) that monitor many PCs at once — this is beyond a single laptop's built-in settings.
  • Backup & recovery: File History and "Reset this PC" are Windows' built-in recovery options; in companies, full disk imaging and offsite backups add further protection.

Viva Questions & Answers:

1. What is the difference between a Standard user and an Administrator account?

A Standard user can run applications and change personal settings but cannot install software system-wide or change security settings. An Administrator has full control, including installing software and managing other accounts.

2. What is Microsoft Defender?

It is Windows' built-in, free antivirus and anti-malware protection that scans files and monitors the system in real time.

3. What is a firewall and why is it needed?

A firewall filters incoming and outgoing network traffic based on rules, blocking unauthorized connections while allowing legitimate traffic — this is needed to stop network-based attacks.

4. Why are security updates important?

Updates patch known vulnerabilities that attackers could otherwise exploit; an unpatched system is an easy target.

5. What is the Principle of Least Privilege?

It states that every user/program should have only the minimum access rights needed to perform its task, reducing the damage possible from mistakes or attacks.

Precautions: Do not disable Defender, Firewall, or Updates to "complete" this practical — simply observe and record their current status.

OFFICIAL PRACTICALPractical 2 — Recovery of Windows Machine Passwords Using an Authorized Recovery Utility

🔒 Security Boundary (read first): This practical only covers (a) Windows' own official account-recovery/reset features on your own device, and (b) the concept of password hashing demonstrated with a self-made fictional sample, in an isolated educational way. It does not explain bypassing a Windows login screen, extracting another person's password hash, or accessing any account you do not own or are not explicitly authorized to administer.

Aim: To understand password hashing, authentication, and authorized password-recovery/reset procedures, and to study the legitimate purpose of password-auditing tools like John the Ripper.

🟢 LEVEL 1 — BASIC

A. Simple English

Password hashing means converting a password into a scrambled fixed-length code (a "hash") using a one-way mathematical function, so the original password is never stored directly.

B. Hinglish

Jab aap Windows mein password banate ho, Windows us password ko seedha store nahi karta. Woh password ko ek "hashing function" se guzaar kar ek scrambled code (hash) banata hai aur sirf woh hash store karta hai. Isiliye real password "dikhta" kabhi nahi hai, sirf uska scrambled version store hota hai.

C. Real-life example

Jaise aapke college ID card ka barcode — barcode dekhkar koi seedha aapka naam nahi padh sakta, usko scan karke hi decode hota hai. Password hash bhi kuch aisa hi hai — seedha "ulta" nahi kiya ja sakta.

Important terms:

TermMeaning
AuthenticationProving you are who you claim to be (e.g., entering correct password).
Password resetSetting a brand-new password when the old one is forgotten (old one is discarded).
Password recoveryRegaining access via an officially supported identity-verification process (e.g., email/phone verification for Microsoft accounts).
Password hashThe scrambled, fixed-length representation of a password stored instead of the plain password.
Password-recovery/auditing utilityA tool (e.g., John the Ripper) that security professionals use, with authorization, to test how strong stored password hashes are.

Requirements: Your own Windows PC (for reset/recovery demo) OR an isolated lab VM with instructor permission (for the hashing demo). No real credentials of any other person are used anywhere in this practical.

🟡 LEVEL 2 — INTERMEDIATE (Procedure)

Part A — Reset a local account you own (built-in Windows feature):

  1. On the Windows sign-in screen, click "I forgot my password" (if a password reset disk/key was set up earlier), or
  2. If you are an Administrator on the PC: Settings → Accounts → Family & other users → select the Standard account → Change account type / Reset password (via Local Users and Groups, lusrmgr.msc, Administrator-only).
  3. Set a new, strong password and sign in to confirm it works.

Part B — Recover a Microsoft account (official online process):

  1. Go to Microsoft's official account-recovery page (search "Microsoft account recovery" and use the official account.live.com / account.microsoft.com domain).
  2. Follow identity-verification steps (alternate email/phone/security questions) exactly as Microsoft's own page instructs.
  3. Set a new password once verified.

Part C — Demonstrating password hashing with a fictional sample (isolated lab/VM only):

  1. Open an isolated lab environment (a sandbox VM or a dedicated practice Linux/Windows lab machine set up by your instructor — never your main PC's real account database).
  2. Create a fictional sample text file, e.g. demo.txt containing a made-up username and a self-chosen test password such as student123 (never a real person's password).
  3. Use a hashing demonstration (for example, computing a SHA-256 hash of the test password using the free certutil command already built into Windows: certutil -hashfile demo.txt SHA256) to show how the same input always produces the same fixed-length scrambled output.
  4. John the Ripper (overview only): It is a well-known open-source password-auditing tool used by security professionals to test the strength of password hashes they are authorized to test (e.g., checking if a company's stored hashes would resist common dictionary attacks). In this practical we only study its purpose and interface conceptually using self-created fictional sample hashes in an isolated lab — we do not run it against any real Windows account database.
  5. Record that a hash of the same fictional password always looks the same, but two different fictional passwords give very different hashes (hash "avalanche effect").

Sample observation (illustrative, fictional data only):

student124completely different hex string — tiny change, huge hash difference

Result: Password reset/recovery on an owned account was successfully demonstrated, and the concept of one-way password hashing was observed using fictional sample data.

Troubleshooting:

  • "Reset password" option greyed out — You need Administrator rights; ask the authorized lab administrator.
  • Microsoft recovery says "we couldn't verify your identity" — This is Microsoft's own anti-abuse protection; follow the alternate verification steps it offers (this exists precisely to stop unauthorized account takeover).
  • certutil command not recognized — Make sure you are using Command Prompt (not PowerShell with restricted execution), run as the same user, and check spelling exactly.
🔴 LEVEL 3 — ADVANCED

🟠 Advanced / Extra Knowledge — Salting, hashing, and password storage:

  • Salting: A random value added to each password before hashing so that even identical passwords produce different stored hashes, defeating precomputed "rainbow table" attacks.
  • Why a hash is not the password: Hashing is a one-way function — there's no mathematical "undo" step. Tools like John the Ripper work by hashing many guesses (dictionary words, common passwords) and comparing the results to the stored hash, not by reversing the hash.
  • Password strength: Length and unpredictability matter more than complexity rules alone; a long passphrase is often stronger and easier to remember than a short complex password.
  • Recovery vs Reset comparison:
AspectPassword ResetPassword Recovery
What happensOld password discarded, new one setIdentity verified via alternate channel, access restored
Who can do itAccount owner or authorized AdministratorAccount owner via official provider process
Typical useForgot local PC password, Admin resets itForgot Microsoft/Google account credentials entirely

Viva Questions & Answers:

1. What is the difference between password reset and password recovery?

Reset discards the old password and sets a new one (usually via an Administrator); recovery restores access to an existing account through identity verification without necessarily knowing the old password.

2. Why is a password never stored in plain text?

If the storage is ever breached, plain-text passwords would be immediately usable by an attacker; hashing ensures only a one-way scrambled form is exposed.

3. What is salting and why is it used?

Salting adds random data to each password before hashing so identical passwords produce different hashes, preventing precomputed rainbow-table attacks.

4. What is John the Ripper generally used for?

It is a password-auditing tool security professionals use, with authorization, to test whether stored password hashes are weak enough to be guessed by dictionary or brute-force methods.

5. Why can't a hash be "decrypted" back to the original password?

Hashing is a one-way mathematical function with no inverse; cracking tools work by hashing guesses and comparing results, not by reversing the hash.

Precautions: Only perform Part A/B on accounts you own. Only perform Part C in an isolated lab/VM with fictional data and instructor permission — never against real credential stores.

OFFICIAL PRACTICALPractical 3 — Tracing Email Origin Using an Email Trace Utility

Aim: To study email headers and understand what information they can (and cannot) reveal about an email's origin, using a harmless test email.

🟢 LEVEL 1 — BASIC

A. Simple English

An email header is hidden technical information attached to every email — like a courier's tracking slip — showing which mail servers handled the message and when.

B. Hinglish

Har email ke peeche ek "invisible" tracking information hoti hai jise header kehte hain. Jaise courier parcel pe tracking sticker hota hai jisme route dikhta hai, waise hi email header mein dikhta hai ki email kis server se hoke aayi.

C. Real-life example

Agar aapko ek suspicious "prize winner" email aaye, header check karke aap dekh sakte ho ki woh really us company ke server se aayi thi ya kisi aur jagah se bheji gayi (spoofed) thi.

Key terms:

TermMeaning
Message-IDA unique identifier generated for each email by the sending server.
Received headersA stack of entries, one per server the email passed through, newest on top.
SPFSender Policy Framework — lets a domain publish which mail servers are allowed to send on its behalf.
DKIMDomainKeys Identified Mail — a cryptographic signature proving the message content wasn't altered in transit.
DMARCA policy that tells receiving servers what to do if SPF/DKIM checks fail (e.g., reject, quarantine).
Email spoofingForging the "From" address to make an email look like it's from someone else.
🟡 LEVEL 2 — INTERMEDIATE (Procedure)

Requirements: Any email account (e.g., Gmail), and one test/harmless email (send yourself a test mail).

  1. Open Gmail in a browser → open the test email.
  2. Click the three-dot menu (⋮) at the top-right of the opened email → select "Show original" (menu label may change between Gmail versions).
  3. A new tab opens showing the full raw header text and a "Download Original" option.
  4. Locate the Received: lines (read bottom-to-top for the path from sender to you), the Message-ID:, Date:, and the SPF/DKIM/DMARC result line Gmail adds near the top.
  5. Note any IP addresses shown in the Received: lines.

Sample fictional header excerpt (illustrative example only):

Delivered-To: student.test@example.com
Received: from mail-server-42.examplemail.com (203.0.113.5)
        by mx.google.com; Mon, 09 Nov 2026 10:15:02 -0800
Message-ID: <CA+fictional123@mail.examplemail.com>
Date: Mon, 09 Nov 2026 10:14:55 +0530
From: "Demo Sender" <demo.sender@example.com>
SPF: PASS with IP 203.0.113.5
DKIM: PASS
DMARC: PASS

Line-by-line explanation:

  • Received — shows which server (and its IP, 203.0.113.5 here) handed the email to Google's servers.
  • Message-ID — a unique tag created by the sending server; helps trace the specific message in logs.
  • SPF/DKIM/DMARC: PASS — the receiving server confirms this server was authorized to send for that domain and the content wasn't tampered with.

Result: The origin-related fields of a test email header were successfully identified and interpreted.

Troubleshooting:

  • "Show original" missing — Menu wording differs by email provider/version; look for "View message source" or similar.
  • SPF/DKIM shows FAIL/NEUTRAL on a real email — This is a legitimate warning sign of possible spoofing; treat such emails cautiously, don't click links.
  • Too many Received lines, confusing order — Always read Received headers bottom-to-top; the bottommost is closest to the original sender.
🔴 LEVEL 3 — ADVANCED

🟠 Advanced / Extra Knowledge:

  • What can be inferred: Which mail server relayed the message, approximate sending time, and whether the sending server was authorized (SPF/DKIM/DMARC pass/fail).
  • What cannot be reliably inferred: The sender's exact personal identity or precise physical device — an IP address usually identifies a mail server (often shared by thousands of users, e.g., a webmail provider), not the individual's computer.
  • Why apparent "From" address isn't proof: The "From" field is just a text field the sender's software fills in — without SPF/DKIM/DMARC checks passing, it can be freely forged (spoofing).
  • Handling suspicious emails safely: Do not click links or download attachments; report/mark as phishing; verify through an independent channel (e.g., call the organization using a known number, not one from the email).

Viva Questions & Answers:

1. What is a Message-ID in an email header?

A unique identifier assigned by the sending mail server to that specific message, useful for tracking in server logs.

2. What do SPF, DKIM, and DMARC each check?

SPF checks if the sending server is authorized for that domain; DKIM verifies the message wasn't altered using a cryptographic signature; DMARC defines what to do if SPF/DKIM fail.

3. Why might an IP address in a header not identify the actual sender's device?

The IP often belongs to a shared mail server (e.g., a webmail provider's infrastructure) used by many people, not the sender's personal computer.

4. What is email spoofing?

Forging the "From" address or header fields to make an email appear to come from a different, often trusted, sender.

5. In what order should "Received" headers be read?

Bottom to top — the bottommost entry is closest to the original sending server, and the topmost is the last server before delivery to you.

Precautions: Use only your own test emails. Never use this knowledge to track, identify, or harass a private individual.

OFFICIAL PRACTICALPractical 4 — Use of Keylogger and Anti-Keylogger to Secure Your System

🔒 Safety note: This manual does not provide or describe a functioning keylogger (no covert keystroke capture, stealth, or credential-collection instructions). Instead, this practical teaches the same defensive concepts through safe, legitimate inspection techniques.

Aim: To understand keylogger threats conceptually and to practice safe defensive techniques (Windows Security scanning, startup-program inspection) that protect against such threats.

🟢 LEVEL 1 — BASIC

A. Simple English

A keylogger is software or hardware that records every key you press, which attackers can misuse to steal passwords. An anti-keylogger/antivirus detects and blocks such tools.

B. Hinglish

Keylogger ek aisa program/device hai jo aapki har keyboard key-press ko chup-chaap record kar leta hai — jaise koi invisible CCTV camera aapke keyboard par laga ho. Agar koi aisa malicious tool aapke PC mein chal raha ho, toh woh aapke passwords bhi chura sakta hai. Anti-keylogger/antivirus is tarah ke suspicious tools ko dhoondh kar block karta hai.

C. Real-life example

College cyber-cafe ke shared computer par agar koi unknown ".exe" startup mein chal raha ho, woh keylogger ho sakta hai — isliye apna net-banking kabhi shared/public PC par mat kholo.

Terms: Hardware keylogger (physical USB device between keyboard and PC) vs Software keylogger (a program running in the background); legitimate monitoring (parental control software disclosed to the user) vs unauthorized surveillance (installed secretly — illegal in most jurisdictions without consent).

🟡 LEVEL 2 — INTERMEDIATE (Safe Defensive Procedure)
  1. Open Windows Security → Virus & threat protection → "Quick scan". Note duration and result.
  2. Create a designated safe sample folder, e.g. C:\Users\<you>\Documents\LabTest, and place only plain harmless text files inside it (no executables). Run a "Custom scan" targeted at this folder to practice scanning a specific location.
  3. Inspect installed applications: Settings → Apps → Installed apps. Scan the list for anything you don't recognize installing.
  4. Inspect startup programs: Task Manager (Ctrl+Shift+Esc) → Startup apps tab. Note every entry and its publisher; anything with no publisher name or an unfamiliar name deserves a closer (not execution-based) look — right-click → search the exact file name online via the publisher's official site before deciding.
  5. Do not open or run any unfamiliar file you find — simply note its name/location/publisher for investigation.
  6. If unauthorized monitoring is ever suspected on a shared/lab PC, report it immediately to the lab in-charge/IT admin rather than attempting to remove it yourself.

EICAR test file (optional, instructor-supervised only): EICAR is a globally recognized, completely harmless text string that all antivirus products are designed to flag as a "virus" purely for testing detection — it contains no real malicious code. If your instructor wants to demonstrate antivirus detection, search for the official EICAR test file page (eicar.org) and follow its own instructions; this manual does not embed or auto-download the file.

Sample observation (illustrative):

CheckResult
Quick scanNo threats found
Startup appsAll recognized, from verified publishers
Unknown installed appsNone found

Result: Defensive inspection of the system for suspicious monitoring software was successfully carried out using only safe, built-in Windows tools.

Troubleshooting:

  • Custom scan option greyed out — Ensure Microsoft Defender is the active antivirus (not disabled by a third-party AV); check Windows Security → Virus & threat protection settings.
  • Unknown startup entry found — Do not run it; note its exact file path and ask your instructor/IT admin to verify it, or research the exact filename on the publisher's official website.
  • Downloaded "anti-keylogger" tool asks for odd permissions — Only install endpoint-security tools from verified, well-known vendors; unknown "security" tools are sometimes malware themselves.
🔴 LEVEL 3 — ADVANCED

🟠 Advanced / Extra Knowledge — Endpoint detection & behavioral monitoring:

  • Modern endpoint protection doesn't just match known virus "signatures" — it also watches behavior (e.g., a process hooking into keyboard input APIs) to catch new/unknown threats (heuristic/behavioral detection).
  • On-screen keyboards and keystroke-scrambling input methods are sometimes used on high-security terminals (e.g., some banking kiosks) specifically to defeat hardware keyloggers.
  • Incident response basics: isolate the device from the network, don't delete evidence, change passwords from a known-clean device, and report to IT/security team.

Viva Questions & Answers:

1. What is the difference between a hardware and a software keylogger?

A hardware keylogger is a physical device placed between the keyboard and the computer; a software keylogger is a program running on the operating system that intercepts keystrokes.

2. Why is unauthorized keystroke monitoring dangerous?

It can silently capture passwords, personal messages, and financial details without the victim's knowledge or consent.

3. What is the EICAR test file used for?

It's a standardized, harmless text string used to verify that antivirus software correctly detects and flags test "threats" without using real malware.

4. How can checking Task Manager's Startup tab help detect suspicious software?

Malware often configures itself to auto-start; reviewing unfamiliar startup entries and their publishers can reveal unauthorized software.

5. What should you do if you suspect unauthorized monitoring software on a shared PC?

Report it immediately to the IT administrator/lab in-charge rather than attempting to remove or investigate it yourself.

Precautions: Never download, write, or run an actual keylogger "to test it." Only download security tools from official, well-known vendor sites.

OFFICIAL PRACTICALPractical 5 — Encrypting and Decrypting a Message Using a Simple Transposition Cipher

Aim: To encrypt and decrypt a message using a columnar transposition (permutation) cipher, and verify that decryption recovers the original plaintext.

🟢 LEVEL 1 — BASIC

A. Simple English

A transposition cipher encrypts a message by rearranging (permuting) the positions of its letters according to a key, without changing the letters themselves — unlike a substitution cipher, which replaces letters with different ones.

B. Hinglish

Transposition cipher mein letters change nahi hote, sirf unki jagah (position) badal di jaati hai — jaise ek jumbled word puzzle. Substitution cipher mein letters replace hote hain (jaise A ko D se), lekin transposition mein sab letters wahi rehte hain, bas order alag ho jaata hai.

C. Real-life example

Jaise exam seating arrangement mein roll numbers same rehte hain par unki table-row assignment shuffle ho jaati hai — data wahi hai, sirf arrangement badla hai.

Terms: Plaintext (original message), Ciphertext (scrambled output), Key (defines the column reading order), Encryption/Decryption.

🟡 LEVEL 2/3 — ALGORITHM, WORKED EXAMPLE & C PROGRAM

Algorithm (Columnar Transposition):

  1. Remove spaces from plaintext (for simplicity in this beginner version).
  2. Choose a key = a sequence of distinct digits, e.g. 3142 (length = number of columns).
  3. Write the plaintext row-by-row into a grid with that many columns; pad the last row with X if incomplete.
  4. Encrypt: Read the grid column-by-column in the order: find the column under digit '1', write it out, then digit '2', then '3', etc.
  5. Decrypt: Rebuild the grid column-by-column in the same digit order (you know how many rows/columns from the key and ciphertext length), then read row-by-row to recover the plaintext.

Worked Example:

Plaintext: ATTACKATDAWN (12 letters, already fits evenly)   Key: 3142 (4 columns, 3 rows)

Col 0Col 1Col 2Col 3
ATTA
CKAT
DAWN

Key digits by column: Col0='3', Col1='1', Col2='4', Col3='2'. Reading order (digit 1→2→3→4): Col1, Col3, Col0, Col2.

  • Col1 (digit 1) = T,K,A → "TKA"
  • Col3 (digit 2) = A,T,N → "ATN"
  • Col0 (digit 3) = A,C,D → "ACD"
  • Col2 (digit 4) = T,A,W → "TAW"

Ciphertext = TKAATNACDTAW

Decryption rebuilds the same grid column-by-column in order Col1,Col3,Col0,Col2 from the ciphertext, then reads row-wise to get back ATTACKATDAWN. ✔ Reversible.

Edge case: If plaintext length isn't a multiple of the number of columns, pad with X at the end before encrypting; after decrypting, trailing X padding can be trimmed by the student if it's clearly not part of the original message.

Complete C Program (columnar transposition, encryption + decryption):

#include <stdio.h>
#include <string.h>
#include <ctype.h>

#define MAXLEN 200

/* Removes spaces from input string */
void removeSpaces(char *str) {
    int i, j = 0;
    char temp[MAXLEN];
    for (i = 0; str[i]; i++) {
        if (!isspace((unsigned char)str[i])) temp[j++] = toupper(str[i]);
    }
    temp[j] = '\0';
    strcpy(str, temp);
}

int main() {
    char plain[MAXLEN], key[20], cipher[MAXLEN], decrypted[MAXLEN];
    int i, j, r, c, rows, cols, len;

    printf("Enter plaintext (no need to remove spaces manually): ");
    fgets(plain, MAXLEN, stdin);
    plain[strcspn(plain, "\n")] = '\0';
    removeSpaces(plain);

    printf("Enter numeric key (distinct digits, e.g. 3142): ");
    scanf("%s", key);
    cols = strlen(key);
    len = strlen(plain);
    rows = (len + cols - 1) / cols;      /* ceil division */

    /* Pad with X if needed */
    for (i = len; i < rows * cols; i++) plain[i] = 'X';
    plain[rows * cols] = '\0';
    len = rows * cols;

    char grid[20][20];
    int pos = 0;
    for (r = 0; r < rows; r++)
        for (c = 0; c < cols; c++)
            grid[r][c] = plain[pos++];

    /* ---- ENCRYPTION: read columns in key-digit order 1..cols ---- */
    int cipherPos = 0;
    for (int digit = '1'; digit < '1' + cols; digit++) {
        for (c = 0; c < cols; c++) {
            if (key[c] == digit) {
                for (r = 0; r < rows; r++)
                    cipher[cipherPos++] = grid[r][c];
            }
        }
    }
    cipher[cipherPos] = '\0';
    printf("\nCiphertext: %s\n", cipher);

    /* ---- DECRYPTION: rebuild grid column by column, same order ---- */
    char grid2[20][20];
    pos = 0;
    for (int digit = '1'; digit < '1' + cols; digit++) {
        for (c = 0; c < cols; c++) {
            if (key[c] == digit) {
                for (r = 0; r < rows; r++)
                    grid2[r][c] = cipher[pos++];
            }
        }
    }
    pos = 0;
    for (r = 0; r < rows; r++)
        for (c = 0; c < cols; c++)
            decrypted[pos++] = grid2[r][c];
    decrypted[pos] = '\0';

    printf("Decrypted : %s\n", decrypted);
    return 0;
}

Enter numeric key: 3142

Ciphertext: TKAATNACDTAW
Decrypted : ATTACKATDAWN

Result: The message was successfully encrypted and decrypted using a columnar transposition cipher; the recovered plaintext matched the original.

  • Decrypted text ends with extra X's — Normal padding artifact; these are not part of the original message if the original length wasn't a multiple of the key length.
  • Wrong key format — The key must use distinct digits from 1 up to the column count (e.g., for 4 columns: digits 1,2,3,4 in some order).

Viva Questions & Answers:

1. How does a transposition cipher differ from a substitution cipher?

Transposition rearranges the positions of the original letters; substitution replaces letters with different ones. Transposition keeps letter identity, changes order; substitution keeps order, changes identity.

2. What is the role of the key in a columnar transposition cipher?

It defines the number of columns and the order in which those columns are read out during encryption (and rebuilt during decryption).

3. Why is padding sometimes needed?

If the plaintext length isn't an exact multiple of the key length, extra filler characters (like X) are added to complete the final row of the grid.

4. Is the columnar transposition cipher secure for real use?

No — it is easily broken using frequency analysis and trial column arrangements; it is for educational understanding only.

5. What information is needed to decrypt a transposition ciphertext?

The exact key (column order) and knowledge of the number of columns/rows used during encryption.

OFFICIAL PRACTICALPractical 6 — Caesar Cipher (Variable Key) and 3×3 Hill Cipher

Part A — Caesar Cipher with Variable Key

🟢 LEVEL 1 — BASIC

A. Simple English

The Caesar cipher shifts every letter of the plaintext forward by a fixed number of positions (the key, k) in the alphabet, wrapping around after Z.

B. Hinglish

Caesar cipher mein har letter ko alphabet mein k positions aage shift kar diya jaata hai. Jaise k=3 ho toh A→D, B→E... aur Z ke baad wapas A se shuru (wrap-around).

C. Real-life example

Bachpan ke "secret code" games jaha A=1, B=2 jaise shift karke dost ko message bhejte the — Caesar cipher bilkul wahi concept hai, bas thoda formal.

Formulas (letter index x: A=0...Z=25, key k):

OperationFormula
EncryptionE(x) = (x + k) mod 26
DecryptionD(x) = (x − k + 26) mod 26

Uppercase and lowercase are handled separately (preserve case); non-letters (spaces, punctuation) are left unchanged.

🟡 LEVEL 2/3 — Worked Example, Table, C Program

Worked example: Plaintext = "HELLO", key k = 3

Letterx(x+3) mod 26Cipher letter
H710K
E47H
L1114O
L1114O
O1417R

Ciphertext = KHOOR. Decryption with k=3: K(10)→H(7), H(7)→E(4), O(14)→L(11), O(14)→L(11), R(17)→O(14) = HELLO ✔ recovered.

Complete C Program (handles variable key, negative/large keys, upper+lower case, non-letters unchanged):

#include <stdio.h>
#include <string.h>
#include <ctype.h>

int main() {
    char text[200];
    int k;

    printf("Enter plaintext: ");
    fgets(text, sizeof(text), stdin);
    text[strcspn(text, "\n")] = '\0';

    printf("Enter key (any integer, + or -): ");
    scanf("%d", &k);

    k = ((k % 26) + 26) % 26;   /* normalize key to 0-25, handles negative/large keys */

    char cipher[200];
    for (int i = 0; text[i]; i++) {
        char ch = text[i];
        if (isupper((unsigned char)ch))
            cipher[i] = (char)(((ch - 'A' + k) % 26) + 'A');
        else if (islower((unsigned char)ch))
            cipher[i] = (char)(((ch - 'a' + k) % 26) + 'a');
        else
            cipher[i] = ch;   /* spaces, punctuation unchanged */
    }
    cipher[strlen(text)] = '\0';
    printf("Encrypted: %s\n", cipher);

    /* Decryption: shift back by k */
    char decrypted[200];
    for (int i = 0; cipher[i]; i++) {
        char ch = cipher[i];
        if (isupper((unsigned char)ch))
            decrypted[i] = (char)(((ch - 'A' - k + 26) % 26) + 'A');
        else if (islower((unsigned char)ch))
            decrypted[i] = (char)(((ch - 'a' - k + 26) % 26) + 'a');
        else
            decrypted[i] = ch;
    }
    decrypted[strlen(cipher)] = '\0';
    printf("Decrypted: %s\n", decrypted);
    return 0;
}

Part B — 3×3 Hill Cipher

🟢 LEVEL 1 — BASIC

A. Simple English

The Hill cipher encrypts blocks of letters together using matrix multiplication, instead of one letter at a time.

B. Hinglish

Hill cipher mein letters ko group (block) mein encrypt kiya jaata hai using matrix maths — ek letter nahi, balki 3-3 letters ka block ek saath transform hota hai key-matrix ke through.

C. Real-life example

Jaise ek group photo mein sabhi logon ki position ek formula se rearrange ho jaaye, ek-ek karke nahi — Hill cipher bhi letters ke poore block ko ek matrix-formula se process karta hai.

Convention used in this manual: A=0, B=1, ..., Z=25. Plaintext is split into blocks of 3 letters (a column vector P). Encryption: C = K × P mod 26. Decryption: P = K⁻¹ × C mod 26.

🟡 LEVEL 2/3 — Key Matrix, Determinant, Inverse, Worked Example, C Program

Key matrix used (a standard, well-known teaching example with a valid inverse mod 26):

6241
131610
201715

Step 1 — Determinant:

det(K) = 6(16×15 − 10×17) − 24(13×15 − 10×20) + 1(13×17 − 16×20)
= 6(240−170) − 24(195−200) + 1(221−320)
= 6(70) − 24(−5) + (−99) = 420 + 120 − 99 = 441

441 mod 26 = 441 − 416 = 25. Check gcd(25, 26) = 1 ✔ — the matrix is invertible mod 26 (this is required; a key matrix must always satisfy this before use).

Step 2 — Modular inverse of determinant: We need x such that 25x ≡ 1 (mod 26). Since 25 ≡ −1 (mod 26), 25 × 25 = 625 = 24×26 + 1 ≡ 1 (mod 26). So det⁻¹ mod 26 = 25.

Step 3 — Inverse key matrix (computed via adjugate method × det⁻¹ mod 26 — standard, verified teaching result):

8510
21821
21128

(Verification check: K × K⁻¹ mod 26 should give the Identity matrix — students should verify at least one row by hand multiplication as a self-check exercise.)

Worked example: Plaintext block "ACT" → A=0, C=2, T=19. Column vector P = [0, 2, 19]ᵀ

C = K×P mod 26:

  • Row1: 6×0 + 24×2 + 1×19 = 0+48+19 = 67 → 67 mod 26 = 15 → "P"
  • Row2: 13×0 + 16×2 + 10×19 = 0+32+190 = 222 → 222 mod 26 = 14 → "O"
  • Row3: 20×0 + 17×2 + 15×19 = 0+34+285 = 319 → 319 mod 26 = 7 → "H"

Ciphertext block = "POH". Decrypting POH with K⁻¹ recovers "ACT" exactly (standard verified result for this classic key matrix).

Padding rule: If the plaintext length is not a multiple of 3, pad with 'X' at the end to complete the final block.

Complete C implementation (3×3 Hill cipher, fixed key matrix and its inverse hard-coded for this lab):

#include <stdio.h>
#include <string.h>
#include <ctype.h>

int K[3][3]  = {{6,24,1},{13,16,10},{20,17,15}};      /* Key matrix */
int Ki[3][3] = {{8,5,10},{21,8,21},{21,12,8}};        /* Verified inverse mod 26 */

void multiply(int M[3][3], int vec[3], int out[3]) {
    for (int i = 0; i < 3; i++) {
        int sum = 0;
        for (int j = 0; j < 3; j++) sum += M[i][j] * vec[j];
        out[i] = ((sum % 26) + 26) % 26;
    }
}

int main() {
    char text[200];
    printf("Enter plaintext (letters only, will be padded to multiple of 3): ");
    fgets(text, sizeof(text), stdin);
    text[strcspn(text, "\n")] = '\0';

    /* Keep only letters, uppercase */
    char clean[200]; int j = 0;
    for (int i = 0; text[i]; i++)
        if (isalpha((unsigned char)text[i])) clean[j++] = toupper(text[i]);
    while (j % 3 != 0) clean[j++] = 'X';   /* padding */
    clean[j] = '\0';

    int n = strlen(clean);
    char cipher[200];
    for (int b = 0; b < n; b += 3) {
        int vec[3] = { clean[b]-'A', clean[b+1]-'A', clean[b+2]-'A' };
        int out[3];
        multiply(K, vec, out);
        cipher[b]=out[0]+'A'; cipher[b+1]=out[1]+'A'; cipher[b+2]=out[2]+'A';
    }
    cipher[n] = '\0';
    printf("Encrypted: %s\n", cipher);

    char decrypted[200];
    for (int b = 0; b < n; b += 3) {
        int vec[3] = { cipher[b]-'A', cipher[b+1]-'A', cipher[b+2]-'A' };
        int out[3];
        multiply(Ki, vec, out);
        decrypted[b]=out[0]+'A'; decrypted[b+1]=out[1]+'A'; decrypted[b+2]=out[2]+'A';
    }
    decrypted[n] = '\0';
    printf("Decrypted: %s\n", decrypted);
    return 0;
}

Encrypted: POH

Common errors:

  • Using a key matrix with det having a common factor with 26 — it will not be invertible; always check gcd(det mod 26, 26)=1 first.
  • Mismatched row/column convention — be consistent about treating plaintext as a column vector throughout.
  • Forgetting to pad — a block must always contain exactly 3 letters.
🟠 Advanced — Known-plaintext weakness: If an attacker obtains enough matching plaintext/ciphertext block pairs, linear algebra can be used to solve for the key matrix itself — this makes Hill cipher unsuitable for real confidential communication today; it remains valuable only for teaching matrix-based cryptography concepts.

Viva Questions & Answers (Practical 6 — both parts):

1. Why is Caesar cipher considered insecure today?

It has only 25 possible keys, making it trivially breakable by brute force in seconds.

2. What does "mod 26" mean in these ciphers and why 26?

It means taking the remainder after dividing by 26, which wraps the result back into the English alphabet's 26 letters (A–Z).

3. Why must the Hill cipher key matrix's determinant be coprime with 26?

Only then does the determinant have a modular inverse mod 26, which is required to compute the matrix inverse needed for decryption.

4. What is the known-plaintext weakness of the Hill cipher?

If enough plaintext-ciphertext block pairs are known, the key matrix can be algebraically solved for using linear algebra, breaking the cipher.

5. How is a letter represented numerically in the Hill cipher convention used here?

A=0, B=1, ..., Z=25, with plaintext blocks represented as column vectors of these numbers.

OFFICIAL PRACTICALPractical 7 — Creating a Digital Signature Document Using a Cryptographic Tool

Aim: To generate a key pair, digitally sign a test document, verify the signature, and observe verification failure when the document is modified — using OpenSSL.

🟢 LEVEL 1 — BASIC

A. Simple English

A digital signature is a cryptographic proof, created with a private key, that a specific document came from a specific signer and was not altered — anyone with the matching public key can verify it.

B. Hinglish

Digital signature ek cryptographic "seal" hai jo private key se banta hai. Isse teen cheezein prove hoti hain: (1) document genuinely usi sender se aaya, (2) document mein koi tampering nahi hui, (3) sender baad mein "maine sign nahi kiya" nahi keh sakta (non-repudiation).

C. Real-life example

Jaise aap ek important assignment PDF college ko bhejte ho aur usko digitally sign karte ho — agar koi beech mein file change kar de, verification fail ho jaayega, bilkul jaise ek torn/tampered stamp paper pakda jaata hai.

Terms:

TermMeaning
Hash functionConverts a document into a short fixed-length fingerprint; any change to the document changes the hash completely.
Private keySecret key, known only to the signer, used to create the signature.
Public keyShareable key, used by anyone to verify a signature made with the matching private key.
IntegrityAssurance that content was not altered.
AuthenticityAssurance of who really created/sent the content.
Non-repudiationSigner cannot later deny having signed the document.

Digital signature vs electronic signature: An electronic signature can be as simple as a typed name or scanned image of a signature (weak proof); a digital signature is cryptographically generated and mathematically verifiable (strong proof).

Digital signature vs encryption: Signing proves authenticity/integrity (uses signer's private key, verified with signer's public key); encryption provides confidentiality (uses recipient's public key to encrypt, recipient's private key to decrypt) — they solve different problems and are often combined.

🟡 LEVEL 2 — INTERMEDIATE (Procedure with OpenSSL)

Requirements: OpenSSL (official project: openssl.org). On Windows, check if it's already installed by opening Command Prompt and typing openssl version. If not found, install a trusted Windows distribution of OpenSSL (search "OpenSSL for Windows" and use a well-known, actively maintained distribution's official download page — e.g., the one linked from the official OpenSSL wiki) — exact download link not embedded here since official links can change; always get it from the project's own site.

  1. Create a lab folder: mkdir C:\SignLab then cd C:\SignLab.
  2. Create a test document: open Notepad, type a short message, save as document.txt inside C:\SignLab.
  3. Generate a private key (RSA, 2048-bit, demonstration only): 
    openssl genpkey -algorithm RSA -out private_key.pem -pkeyopt rsa_keygen_bits:2048
  4. Extract the public key: 
    openssl pkey -in private_key.pem -pubout -out public_key.pem
  5. Sign the document (RSA with SHA-256): 
    openssl dgst -sha256 -sign private_key.pem -out signature.bin document.txt
  6. Verify the signature: 
    openssl dgst -sha256 -verify public_key.pem -signature signature.bin document.txt
    Expected output: Verified OK
  7. Tamper test: Copy document.txt to document_modified.txt, change one word, then run: 
    openssl dgst -sha256 -verify public_key.pem -signature signature.bin document_modified.txt
    Expected output: Verification Failure — proving the signature detects even a one-word change.

Result: A digital signature was generated and verified successfully on an unmodified document, and verification correctly failed on a modified copy, confirming the integrity-checking property.

⚠ Never share or upload private_key.pem anywhere. In this lab it is only a demonstration key for learning, with no real-world trust value.

Troubleshooting:

  • 'openssl' not recognized — OpenSSL's folder isn't in the Windows PATH; reinstall allowing PATH update, or add it manually via Environment Variables settings.
  • "Verification Failure" on the unmodified file too — Check you used the exact same document.txt (not re-saved with different line endings) and the matching public_key.pem/signature.bin pair.
  • Permission denied writing files — Run Command Prompt from a folder you have write access to (avoid system-protected folders).
🔴 LEVEL 3 — ADVANCED

🟠 Advanced / Extra Knowledge — Trust, Certificates & PKI:

  • A self-generated key pair (as in this lab) proves the document wasn't altered since signing, but by itself does not prove the signer's real-world identity — anyone can generate a key pair claiming to be anyone.
  • Public Key Infrastructure (PKI) solves this by having a trusted Certificate Authority (CA) issue a digital certificate binding a public key to a verified real-world identity.
  • Modern alternatives to RSA+SHA-256 include Ed25519 (faster, smaller keys, same security goals) where the chosen tool supports it.
  • Legal validity of digital signatures (e.g., under IT Act provisions) typically requires certificates from licensed Certifying Authorities — a classroom demo key pair has no such legal standing.

Viva Questions & Answers:

1. What three security properties does a digital signature provide?

Authenticity (proves who signed), integrity (proves content wasn't altered), and non-repudiation (signer can't deny signing).

2. Which key is used to sign, and which to verify?

The private key (kept secret by the signer) is used to sign; the corresponding public key (shared openly) is used by anyone to verify.

3. What happens to the signature verification if the document is changed by even one character?

Verification fails, because the hash of the modified document no longer matches the hash that was originally signed.

4. How is a digital signature different from simple encryption?

Signing proves authenticity and integrity using the signer's private key; encryption provides confidentiality using the recipient's public key — they serve different purposes.

5. Why doesn't a self-generated key pair alone prove real-world identity?

Anyone can generate a key pair and label it with any name; real-world identity binding requires a trusted Certificate Authority issuing a certificate as part of a PKI.

Precautions: Use only test/demo documents and demonstration keys; never your real identity documents or production credentials.

OFFICIAL PRACTICALPractical 8 — Sending and Receiving Secret Messages Using Steganography (Steghide)

Aim: To hide a secret text message inside a sample image file (embedding) and successfully retrieve it (extraction) using Steghide, and to understand steganography's purpose and limitations.

🟢 LEVEL 1 — BASIC

A. Simple English

Steganography means hiding the very existence of a secret message inside another ordinary-looking file (the cover file), rather than scrambling the message like cryptography does.

B. Hinglish

Cryptography message ko "scramble" karti hai (dikhta hai ki kuch secret hai, par padh nahi sakte). Steganography isse ek level aage le jaati hai — message ko kisi normal photo/audio ke andar chupa diya jaata hai, taaki kisi ko shak hi na ho ki usme koi secret message hai.

C. Real-life example

Jaise ek normal dikhne wali holiday photo WhatsApp par bheji jaaye, par uske andar ek chhota text message chhupa ho jo sirf sahi passphrase se nikala ja sake — dekhne mein woh sirf ek photo lagti hai.

Terms: Cover file (the ordinary file used to hide data, e.g. a JPEG), Hidden payload (the secret message), Embedding (hiding process), Extraction (retrieval process), Passphrase (password protecting the hidden data).

🟡 LEVEL 2 — INTERMEDIATE (Procedure)

Requirements & Windows note: Steghide is an open-source tool; check its official project page (e.g., its SourceForge project page is the commonly cited official distribution point — always verify you're on the genuine project page before downloading). Native up-to-date Windows builds are not always reliably maintained; a well-supported alternative is installing Steghide inside WSL (Windows Subsystem for Linux), where it's available via the Linux package manager. This manual recommends WSL as a verified-working alternative rather than guessing a Windows installer link.

  1. Set up environment: Either install Steghide natively if a trustworthy current Windows build is available from the official source, or enable WSL (Settings → Apps → Optional features → More Windows features → "Windows Subsystem for Linux", restart, then install a Linux distribution from Microsoft Store) and inside it run sudo apt install steghide.
  2. Prepare a sample image you own (e.g. cover.jpg) and a fictional secret text file secret.txt containing a harmless test message like "Lab test message, not confidential."
  3. Place both files in one working folder, e.g. ~/steglab/ (WSL) or C:\SteghideLab\.
  4. Embed the message: 
    steghide embed -cf cover.jpg -ef secret.txt -sf cover_with_secret.jpg
    It will prompt for a passphrase — choose a test passphrase and remember it.
  5. Extract the message: 
    steghide extract -sf cover_with_secret.jpg
    Enter the same passphrase; it writes out secret.txt again.
  6. Verify: Open the extracted secret.txt and confirm its content matches the original message exactly.

Sample expected output (illustrative):

$ steghide embed -cf cover.jpg -ef secret.txt -sf cover_with_secret.jpg
Enter passphrase: 
Re-Enter passphrase: 
embedding "secret.txt" in "cover.jpg"... done
wrote stego file to "cover_with_secret.jpg".

$ steghide extract -sf cover_with_secret.jpg
Enter passphrase: 
wrote extracted data to "secret.txt".

Result: A fictional text message was successfully embedded into an image cover file and later extracted intact using the correct passphrase, demonstrating steganographic data hiding.

Troubleshooting:

  • "steghide: command not found" — Tool isn't installed in the current environment; re-check installation step or confirm you're inside WSL, not plain Windows Command Prompt.
  • "could not extract any data" — Wrong passphrase, or the file was recompressed/edited after embedding (e.g., resent via an app that recompresses images), which destroys the hidden data.
  • Unsupported cover file format — Steghide supports specific formats (e.g., certain JPEG, BMP, WAV, AU files); check the tool's own documentation for the current supported list.
🔴 LEVEL 3 — ADVANCED

🟠 Advanced / Extra Knowledge:

  • Embedding ≠ Encryption: By default, hiding a message only conceals it; Steghide additionally encrypts the payload using the passphrase, but the core technique's purpose is concealment, and some other steganography tools don't encrypt at all — always check per-tool.
  • Fragility: Re-saving, recompressing, resizing, or converting the cover file after embedding usually destroys the hidden data, since the hiding relies on exact file structure/least-significant-bit patterns.
  • Steganalysis (EXTRA KNOWLEDGE): The study of detecting hidden data's presence, e.g., via statistical anomalies in an image's pixel data — an active cat-and-mouse research area, not expected to be performed at this lab level.

Viva Questions & Answers:

1. What is the key difference between cryptography and steganography?

Cryptography scrambles a message so its content is unreadable, while steganography hides the very existence of the message inside an innocent-looking cover file.

2. What is a "cover file" in steganography?

The ordinary file (e.g., an image or audio file) used to conceal the hidden payload.

3. Why might hidden data be lost after sharing an image on social media?

Many platforms recompress or resize uploaded images, which alters the file structure and destroys the precisely-placed hidden bits.

4. Does embedding a message with Steghide always encrypt it too?

Steghide applies passphrase-based encryption to the payload by default, but this is tool-specific; some steganography tools hide data without any encryption at all.

5. What is steganalysis?

The study and practice of detecting whether a file contains hidden steganographic data, often using statistical analysis.

Precautions: Use only your own sample files and fictional, non-confidential text messages. Never use steganography to hide genuinely illegal or harmful content.
